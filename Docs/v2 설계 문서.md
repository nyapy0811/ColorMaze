## 1. 개요

- v2는 v1을 **완전히 교체**하는 업데이트다. 1인칭 미로 퍼즐이며, 개인 프로젝트(습작)이고 스팀 출시는 희망 사항이다.
- 플레이어는 **색 하나(지금 색)**를 들고 다닌다. 맵의 색 있는 사물에서 색을 흡수해 지금 색에 더하고, 그 색으로 문을 열고 레이저 벽을 지나 목적지에 닿는다.
  - 2026-11-01 개편: 색 오브를 모아 합성기에서 합성해 작동기에 제출하던 방식을 없애고, v1처럼 색을 바로 쌓는 방식으로 돌아왔다(결정 로그 '색 시스템 개편').
- **핵심 루프**
  1. **흡수**: 색 원천(소화기 같은 사물)을 조준해 클릭하면 그 값이 지금 색에 바로 더해진다.
  2. **문**: 지금 색이 문의 요구 색과 정확히 같을 때 클릭하면 문이 열리고(계속 열림), 지금 색은 0이 된다.
  3. **레이저 벽**: 지금 색이 레이저 벽의 색 이상이면 지나갈 수 있고, 지날 때마다 그만큼 빠진다.
  4. **목적지**: 문과 같이, 요구 색과 정확히 같은 색으로 클릭하면 클리어한다.
- 색 원천은 한 번씩만 흡수할 수 있고 색은 더하기만 된다(레이저 벽이 빼는 것 말고). 그래서 **어느 원천을 어느 문에 쓸지** 고르며 길을 찾는 미로가 된다. 난이도는 경로의 복잡도와 문의 개수로 조절한다.
- 월드는 무채색이고, 색으로 상호작용과 구분을 나타낸다(색 원천의 색, 문·레이저 벽·목적지의 요구 색).
- 배경(테마)은 맵마다 다르고, 이야기는 짧은 배경 설정만 둔다(메인 메뉴나 첫 맵에서 암시, 내용 미정).

## 2. 색 값

- **값**: R, G, B 세 채널의 정수 값이다. 단색(빨강 2)과 혼합(빨강 1 파랑 2)이 모두 있다. 채널은 R/G/B 셋으로 고정하고, 색의 다양성은 값의 조합으로 만든다.
- **지금 색**: 플레이어가 드는 값 하나다. 맵은 (0,0,0)에서 시작한다.
- **한도**: 각 채널은 0~5이고 모든 맵이 같다. 흡수한 결과는 채널마다 5로 **자른다**(넘친 값은 사라짐). v1처럼 넘치면 0부터 다시 세는 순환은 없다.
- **요구 색**(문·목적지): 모든 채널이 1 이상이고, 세 채널이 같은 값((1,1,1) 등)은 쓰지 않는다(회색으로 보여 무채색 월드와 헷갈림). 한도(5) 안이다. 레이저 벽 색에 0이 든 채널을 허용할지는 미정이다.
- **색**: 값의 비율을 정규화한 RGB(가장 큰 채널 기준)로 보인다. 그래서 비율이 같으면 크기가 달라도 같은 색이다((1,0,0)과 (2,0,0)). 사물의 밝기는 아트용으로 따로 정한다(값과 무관).
- **발광**: 손 위 구(지금 색)는 자체 발광(Emission)하고, **발광 세기가 세 채널 중 최댓값에 비례**한다. 그래서 크기 차이가 빛의 세기로도 보인다.
- **정확한 값(숫자)**: 'R G B' 숫자 세 개를 작은 상자에 보인다(예: `2 0 0`).
  - 상호작용 거리 안에서 색 원천, 문, 레이저 벽, 목적지를 조준하면 조준점 오른쪽 위에 뜬다.
  - 지금 색은 HUD에 늘 보인다.
  - 맵 위에 늘 붙어 있는 라벨은 쓰지 않는다.
- **판정**: 문과 목적지는 값이 **정확히 같아야** 통과한다(색이 같아 보여도 값이 다르면 거부).

## 3. 흡수

- 조준 + 좌클릭으로 흡수한다. 색 원천의 값이 지금 색에 **바로 더해지고**(채널마다 5로 자름), 원천은 **원래 색을 흑백으로 바꾼 색**이 된다(밝기는 세 채널의 평균).
- 색 원천은 소화기 같은 일상 사물이고(빨간 소화기에서 빨간색을 빨아들이는 느낌), 값은 사물마다 정한 고정값이다(사물의 색과 연동).
- 한 번 흡수한 원천은 체크포인트 복귀나 맵 재시작으로만 다시 흡수할 수 있다.
- 연출: 오른손을 뻗어 빨아들이고, 원천에서 손으로 모이는 짧은 애니메이션(0.5~1초)과 이펙트·소리를 보인다.
- 슬롯이 없으므로 '가득 차서 흡수할 수 없음'은 없다.

## 4. 막힘과 되돌리기

- 색을 빼거나 비우는 장치·키는 없다. 잘못 흡수해 색이 어긋나면 **체크포인트로** 돌아가거나 **처음부터** 다시 한다.
- 막힘(흡수할 원천이 남지 않음, 요구 색을 만들 수 없음 등)은 **재시작으로 푸는 것이 의도**다.
- 합성기와 오브 편집기(필터·복제기·증폭기)는 2026-11-01 개편에서 없앴다.

## 5. 기물

### 5.1 분류

| 계열 | 종류 | 역할 |
|---|---|---|
| 문 계열 | 문, 레이저 벽 | 경로를 막는다. 요구 색으로 열리거나(문) 지나간다(레이저 벽) |
| 작동기 계열 | 목적지 | 요구 색으로 클리어한다 |
| 색상 획득 계열 | 색 원천(추출 오브젝트) | 색을 준다(흡수) |
| 출발점 계열 | 시작 지점, 체크포인트 | 플레이가 시작되는 곳 |

- 계열은 종류마다 하나이고, **성질**은 종류마다 여러 개다: 색상 제출(문, 목적지), 색상 뺄셈연산(레이저 벽), 색상 덧셈연산(색 원천), 일방통행(아직 가진 종류 없음). 코드 이름과 배치 방식(노드 시스템, 설치형, 구역 지정형)은 `Docs/v2 기물 분류.md`에 있다.
- 개편 전의 작동기 계열(일회용·반복 작동기)과 오브 편집기 계열은 색 시스템 개편에서, 계단 계열은 층간 이동을 없애며 지웠다. 지금의 작동기 계열은 목적지를 담는 새 계열이다.

### 5.2 문

- 요구 색을 하나 가진다. 조준 + 좌클릭하면 지금 색과 비교한다.
  - **정확히 같으면** 열리고, 지금 색은 **(0,0,0)으로 비워진다**. 한 번 열린 문은 **계속 열려 있다**.
  - 다르면 열리지 않고 문이 흔들린다(지금 색은 그대로, 글 알림 없음).
- 벽 구간 중간에 폭 1로 끼우고, 문 위로는 벽이 이어진다. 한 구간에 하나, 대각선 구간에도 둘 수 있고, 위치는 0.25유닛 단위로 맞춘다.
- **가운데서 둘로 갈라져 좌우 벽 속으로 밀려 들어가며** 열린다(모든 문 공통). 그래서 문 양옆에 문 폭의 절반만큼 벽이 있어야 한다.
- 요구 색을 보이는 모양은 디자인할 때 정한다.

### 5.3 레이저 벽

- 색(빼는 색)을 하나 가진다. 지금 색의 **모든 채널이 그 색 이상**이면 지나갈 수 있고, 반대쪽으로 **완전히 빠져나갔을 때** 그 색만큼 지금 색에서 뺀다. 들어갔다 되돌아오면 빼지 않는다. **지날 때마다**(양쪽 방향 모두) 뺀다.
- 모자라면 벽처럼 막는다. 지날 수 있는지 미리 보이는 모양은 미정이다.
- 노드 사이 구간 하나가 레이저 벽 하나다. 레이저 프리팹 하나를 구간 길이에 맞게 늘린다(겉모습과 콜라이더가 하나).
- 반투명한 면이고, 발사 장치는 구간 가운데 **천장**에 붙는다.
- 레이저 벽은 막을 뿐이다. v2에는 **의도된 사망 요소가 없다**.

### 5.4 목적지

- 맵당 1개이고 요구 색을 하나 가진다. 문과 같이 조준 + 좌클릭하면 지금 색과 비교해, **정확히 같으면 클리어**한다(다르면 흔들림).

## 6. 체크포인트와 저장

### 6.1 시작 지점과 체크포인트

- 시작 지점과 체크포인트는 **출발점 계열**(플레이가 시작되는 곳)이다.
- **시작 지점**: 맵마다 하나 두는 프리팹(위치·방향)이다. 플레이어는 지금 색 **(0,0,0)**으로 이곳에서 시작한다.
- **체크포인트**는 맵에 놓는 프리팹이고, 플레이어가 닿으면 자동으로 활성화된다. 알아볼 수 있는 모양과 닿았을 때의 효과를 준다(디자인 미정).
- **처음 닿을 때만** 그 순간의 맵과 플레이어 상태를 저장한다(한 번 저장한 체크포인트에는 다시 저장하지 않음): 플레이어 위치, 지금 색, 흡수 상태, 열린 문, 맵 플레이 시간, 활성화된 체크포인트 목록.
- 체크포인트는 선택지가 갈라지는 분기점에 두는 **편의 장치**이고 클리어를 보장하지 않는다. 막힌 상태로 닿아 저장되면 '체크포인트로'와 '이어하기'도 막힌 상태로 돌아가므로 '처음부터'로 푼다.
- **체크포인트로**: 저장한 상태로 되돌린다(씬을 다시 불러오지 않고 오브젝트별로 복원). 시선은 체크포인트가 정한 방향이다. 체크포인트에 닿기 전이면 '처음부터'와 같다.
- **처음부터**: 시작 지점부터 완전히 초기화한다.
- 둘 다 검은 화면 페이드를 넣는다.
- 맵 밖으로 떨어지면(안전망) 마지막 체크포인트 위치(없으면 시작 지점)로 옮기기만 한다. 진행은 그대로이고 연출은 없다.

### 6.2 저장

- v2 전용 저장 파일(시맨틱 버전 필드)을 쓴다. 담는 것은 아래와 같다.
  - 맵별 클리어 기록, 최고 클리어 시간, (수집 요소를 넣으면) 최고 수집률 (맵 id로 저장)
  - 지금 플레이 중인 맵의 마지막 체크포인트 1개 (맵 id와 맵 버전 포함)
- **저장 시점**: 체크포인트에 닿을 때와 클리어할 때. 마지막 체크포인트 뒤의 진행은 게임을 끄면 사라진다.
- **이어하기**: 메인 메뉴(저장된 체크포인트가 있을 때)와 맵 선택 화면에서 마지막 체크포인트부터 시작한다.
- 체크포인트 기록은 '처음부터'를 누르거나 클리어하면 지운다. 다른 맵의 체크포인트가 저장된 채로 새 맵을 시작하면 경고하고, 체크포인트가 저장된 맵을 처음부터 시작하면 확인 창을 띄운다.
- 체크포인트 기록의 맵 버전이 맵 목록의 버전과 다르면(퍼즐에 영향을 주는 수정을 한 뒤) 그 기록을 버린다. 이어하기 버튼만 사라지고 알림은 없다.
- 맵별 시도 횟수는 기록하지 않는다.
- 설정은 v1처럼 `settings.json`에 따로 두고, v1과 같은 형식이라 v1 설정이 이어진다. 설정 화면의 저장 초기화는 v2 저장 파일을 지운다.
- Steam 업적과 클라우드 세이브는 지금 만들지 않고, 저장 구조만 나중에 맞출 수 있게 설계한다(저장 시각 같은 필드).

## 7. 플레이어와 연출

### 7.1 조작

- 1인칭 시점, 조준 + 좌클릭 상호작용. 상호작용 거리는 흡수·문·목적지 모두 같은 값(3)이다(v1의 1.3에서 조정). 큰 기물은 표면 어디를 조준해도 된다.
- 키보드 + 마우스로 조작하고, 게임패드는 일단 지원하지 않는다.
- **점프**는 유지하지만 **스페이스바 점프로만 갈 수 있는 길은 두지 않는다**. 길을 막는 것은 벽과 문 계열뿐이라 점프 높이 제한은 두지 않는다.
- 이동 속도·가속은 모든 맵이 같은 값이고, 미로를 설계한 뒤 v1 값(속도 5, 가속 0.1초)에서 조정한다. 점프 높이·거리도 미로를 설계한 뒤 맞추고, 카메라 눈높이는 지금 값을 기준으로 미세 조정한다.
- 팝업(확인 창 등)이 열려 있으면 이동과 시점 회전을 막는다. 팝업은 ESC나 닫기 버튼으로 닫는다. ESC는 팝업을 먼저 닫고, 팝업이 없을 때 일시정지 메뉴를 연다.

### 7.2 조준

- 조준점은 '+' 모양이고 흰색으로 고정한다(색이 바뀌지 않음).
- 상호작용할 수 있는 오브젝트에는 **늘 약한 강조**(빛남 등, 색 미정, 코어 루프 동안은 숨 쉬듯 약하게 빛남)를 둔다(흡수한 원천과 열린 문은 꺼짐). 조준했을 때는 값 표시 말고 따로 주는 피드백이 없다.
- 흡수한 원천은 무채색이라 바로 구분되고, 조준해도 값이 뜨지 않는다.

### 7.3 뷰모델 (지금 색)

- 화면 우하단에 손이 보이고, **지금 색이 오른손 위에 3D 구 하나로 떠 있다**. 구 색은 머티리얼 색을 실행 중에 바꿔 그리고, 발광 세기가 크기를 보인다(2절). (0,0,0)일 때의 모양은 미정이다.
- 흡수할 때는 오른손을 뻗어 빨아들인다(모이라 느낌).

### 7.4 월드와 그래픽

- **아트 스타일**은 복셀 아트다. 직접 만드는 모델은 MagicaVoxel로 만들고, 구입 에셋도 복셀 스타일만 쓴다. v1의 복셀 격자와 달리 맵은 노드 시스템으로 짓고, 복셀은 모델의 겉모습이다. 값에 따라 색을 칠하는 부분은 별도 렌더러로 나눠 만든다. 복셀 크기는 **1유닛 = 20칸**(1복셀 = 0.05유닛, 기준 치수가 모두 정수 칸: 모듈 5, 벽 두께 4, 기둥 6, 판 2, 벽의 키 60, 문 20 × 40)이고 모든 모델이 같은 크기를 쓴다(손 뷰모델만 만들 때 정함). 모델은 `.vox` 그대로 `Assets`에 두고 전용 가져오기 코드가 메시와 재질을 만든다(크기·축·기준점·칠하는 부분 나누기를 한 곳에서 정함, 같은 색 면은 합침). 가져오기 코드는 메인 세션이, 모델링 규칙(칠하는 색 칸 등)은 아트 세션이 정한다(13절). 모델링 규칙(팔레트의 칠하는 색 칸, 회색만 쓰기, 폴더 `Assets/Models`, 부품·축·기준점)은 `Docs/v2 복셀 모델링 규칙.md`에 있다.
- **무채색 월드**는 회색 머티리얼로 시작하고, 필요해지면 채도를 낮추는 셰이더를 필요한 머티리얼에만 쓴다. 화면 전체를 회색으로 만드는 포스트프로세싱은 색 오브젝트까지 회색이 되므로 쓰지 않는다. 색이 있는 오브젝트는 원래 색을 유지한다.
- 벽·기둥·바닥·천장은 각자의 디자인으로 구분한다(형태 미정). 벽과 바닥 사이에 경계선은 일단 두지 않는다.
- 발광은 자체 발광만 쓰고 포인트 라이트는 두지 않는다. 손 위 구 주위의 입자 효과는 미정이다.
- **포스트프로세싱**: 모션 블러, 비네트, 상호작용 때 쓰는 화면 효과는 설정에서 켜고 끈다. 블룸·톤매핑은 미정이다(자체 발광이 번져 보이려면 블룸이 필요).
- 라이팅(환경광·방향광)은 개발하면서 정한다.
- **성능**: 120fps를 목표로, 60fps를 기준(최소)으로 둔다. 그리기 최적화는 지금 켜진 설정(GPU Resident Drawer, SRP Batcher, 정적 배칭)으로 시작하고, 부담이 느껴지면 기법을 더한다.

### 7.5 소리

- 소리는 **배경음악 / 배경효과음 / 상호작용음 / UI음 / 효과음** 5종으로 나눈다. BGM 스타일과 동시에 울리는 최대 개수는 미정이다.
- 음성은 없다.

## 8. UI와 메뉴

### 8.1 화면 공통

- 기본 해상도는 1920×1080이고 여러 해상도를 지원한다(UI 레이아웃은 1920×1080 기준).
- 폰트와 색 표시가 아닌 UI(조준점, 버튼, 패널, 글자)의 색 원칙은 미정이다. 텍스트는 나중에 다국어를 넣을 수 있게 만든다.
- **글로 띄우는 짧은 알림은 없다.** 실패는 연출로 알린다(색이 맞지 않으면 문·목적지가 흔들림).
- **지금 색 HUD**: 지금 색의 값(R G B 숫자)과 색을 늘 보인다. 자리와 모양은 만들 때 정한다. 인벤토리 창(Tab)은 개편에서 없앴다.
- 색맹 대응은 일단 하지 않는다(값은 숫자로도 확인할 수 있음).

### 8.2 안내

- 마커, 스테이지 가이드, 튜토리얼 문구, 기물 안내 팝업은 없다. **맵 설계로만 유도**한다.

### 8.3 메뉴 흐름

- **메인 메뉴**: Play를 누르면 맵 선택 화면으로 바로 간다. 이어하기 버튼(저장된 체크포인트가 있을 때)이 있다. 맵 에디터·커스텀 맵 버튼은 숨긴다.
- **맵 선택 화면**: v1 스테이지 선택 화면을 고쳐 쓴다. 맵 목록, 미리보기, Play, 맵별 클리어 표시와 최고 클리어 시간이 있다.
  - 스테이지/챕터 구분은 없다.
  - 모든 맵이 처음부터 열려 있다.
  - 목록 순서가 '다음 맵' 순서다.
- **일시정지 메뉴**: 계속하기 / 처음부터 / 체크포인트로 / 설정 / 메인메뉴. 진행이 사라지는 세 버튼(처음부터, 체크포인트로, 메인메뉴)은 확인 창을 띄운다.
- **클리어 화면**: 새로 디자인한다.
  - 클리어 시간과 통계를 보인다. 통계는 수집률이고, 수집 요소를 넣을 때부터 보인다.
  - '다음 맵' 버튼이 있고, 마지막 맵에서는 맵 선택 화면으로 가는 버튼이 된다.
- **클리어 시간**
  - 이어하기로 나눠 해도 합쳐서 잰다.
  - 일시정지 중에는 멈춘다.
  - 체크포인트로 돌아가도 되돌리지 않고, '처음부터'면 0부터 잰다.
  - 맵별 최고 기록을 저장한다.
- **설정 메뉴**: 접근성을 포함해 새로 설계한다. 지금까지 정해진 항목은 아래와 같고, 나머지(음량을 소리마다 따로 둘지 등)는 설정 화면을 설계하면서 정한다. 색맹 모드는 두지 않는다.
  - 해상도
  - 모션 블러, 비네트, 상호작용 화면 효과 켜고 끄기
  - 소리 5종
- 플레이어가 고르는 난이도 설정은 없다.

## 9. 맵과 맵 제작

### 9.1 맵 구조

- 맵 전체를 벽으로 둘러싼다.
- 맵은 **한 층**이다. 층 사이를 오가는 기물(계단 계열)은 두지 않는다.
- 정답 경로는 여러 개여도 되고, 플레이어는 하나만 찾으면 클리어한다.

### 9.2 벽 노드 시스템

- v1의 블록(복셀) 격자 대신 **노드를 이어 벽을 만든다**. 노드는 정수 좌표(월드 1유닛)에 놓이고, 어느 두 노드든 직선 벽으로 이을 수 있으며(대각선 포함), 한 노드는 여러 노드와 이어질 수 있다.
- **벽 모양**
  - 벽은 0.25유닛 벽 모듈을 반복해 채운다.
  - 모든 노드에 같은 기둥을 놓아 이음새와 0.25 미만으로 남는 길이를 가린다.
  - 벽의 키는 모든 벽이 같다(정수, 3).
  - 모든 노드는 높이 0에 놓는다(경사 벽 없음).
- **콜라이더**는 구간마다 상자 하나다(문이 있는 구간은 문 양옆 둘과 문 위 벽 하나). 벽 모듈 프리팹은 겉모습만 두고, 기둥에는 콜라이더가 있다.
- 벽 재질은 구간마다 고른다.
- **기준 치수**: 코어 루프를 만들 때 회색 상자로 걸어 보며 정했다: 벽 두께 0.2(1유닛 통로의 실제 폭 0.8), 기둥 0.3 × 0.3, 벽의 키 3, 문 폭 1·높이 2.0.
- **바닥·천장**은 벽을 만들 때 자동으로 생긴다.
  - 1×1 칸 타일로 깐다.
  - 모든 노드를 감싸는 사각형 안 전부에 바닥(높이 0)과 천장(벽의 키 높이)을 깐다.
  - 나중에 최적화를 위해 큰 타일을 더할 수 있다.
- **노드 시스템에 넣는 기물**은 문 계열(문, 레이저 벽)이다. 색 원천·목적지·체크포인트·시작 지점은 설치형이다. 구역 지정형(프리팹이 차지하는 칸의 바닥·천장을 비움)은 지금 쓰는 기물이 없다.
- **만드는 시점**: 같은 배치 코드를 쓰되, 유니티 에디터 맵은 에디터에서 미리 만들어 씬에 저장하고(인스펙터 연결과 라이트맵을 그대로 씀), UGC 맵은 불러올 때 런타임에 만든다. 노드를 고쳐 다시 만들 때는 데이터 id로 지금 오브젝트와 비교해 남은 것은 지우지 않고 갱신하므로, 인스펙터로 넣은 값(요구 색 등)이 남는다.
- 노드 시스템은 기본 부모 클래스를 두고 종류별로 상속하는 구조로 준비한다(이동 발판 같은 특수 종류를 나중에 더하기 쉽게).

### 9.3 데이터

- `CustomStageData`에 **nodes**와 **walls** 목록, **버전 필드**를 더한다.
  - 노드: id + 좌표 (x, y, z). id는 맵 안에서 1부터 자동으로 늘어나는 정수이고 지운 번호는 다시 쓰지 않는다. y는 늘 0이다(맵은 한 층).
  - 벽: 양 끝 노드의 id 둘 + 종류(일반 벽 / 레이저 벽) + 종류별 설정(재질, 일반 벽에 끼운 문의 위치와 설정).
- UGC 맵의 id(기물, 끼운 문)도 같은 정수 id 방식을 쓰고, 문 계열 항목에는 요구 색을 담는다.
- v1 필드(blocks, fixtures 등)는 맵 에디터를 v2로 고칠 때 지운다.
- **맵 안 오브젝트 id**: 유니티 에디터 맵의 기물도 맵 안에서 1부터 자동으로 늘어나는 정수 id를 쓴다(체크포인트 스냅샷이 이 id로 기물을 찾음). 에디터 스크립트가 기물을 놓거나 복제할 때 번호를 주고, 겹치면 고친다.
- **맵 목록**: 새로 만드는 맵 목록 애셋 하나에 맵을 순서대로 둔다(맵 id, 씬, 이름, 썸네일, 맵 버전). 목록 순서가 맵 선택 화면과 '다음 맵'의 순서다.
  - 맵 id는 씬 이름과 따로 적은 고정 문자열이라 씬 이름을 바꿔도 기록이 이어진다.
  - 맵 버전은 퍼즐에 영향을 주는 수정을 할 때 올린다.

### 9.4 에디터 도구

- 맵 제작은 **유니티 에디터의 프리팹 방식**이다. 3D 모델은 직접 제작과 에셋 구입을 병행한다(구입 에셋도 복셀 스타일).
- **노드 편집 도구**는 두 부분을 함께 쓴다.
  - 전용 에디터 창: 노드·벽 목록, 선택한 벽의 종류·문 위치 같은 값, '벽 다시 만들기' 같은 버튼.
  - 씬 뷰 조작: 클릭으로 노드를 찍고, 노드를 고른 채 Shift+클릭으로 벽을 잇고(빈 곳이면 노드를 찍고 이어 연달아 그림), 끌어서 옮기고, Delete로 지운다.
- 정수 좌표 스냅은 기본이다. 노드 위를 클릭하면 새 노드 대신 그 노드를 고르고, 같은 자리에 노드가 둘 생기면 자동으로 합친다.
- 유니티 Undo/Redo를 완전히 지원한다. 각도 스냅은 필요하면 더한다.
- **인게임 맵 에디터(UGC)**는 나중에 지원할 예정이고 같은 `CustomStageData` 형식을 쓴다. v1 맵 에디터는 지웠고, 개발 순서의 마지막 '에디터 새로 만들기'에서 노드 방식에 맞춰 새로 만든다.

### 9.5 맵 설계 규칙

- (0,0,0)과 세 채널이 같은 값은 색 원천과 요구 색(문·목적지)에 쓰지 않는다. 요구 색에는 0이 든 값도 쓰지 않는다.
- 색 원천은 서로 겹치게 두지 않는다.
- 색 원천 구성, 초반 맵의 제약, 막다른 길의 밀도 같은 난이도 요소는 맵을 만들면서 정한다. 남는 원천은 따로 계산하지 않는다.
- **길을 막는 것은 벽과 문 계열뿐**이다. 설치형 기물로 길을 막지 않는다(비켜 갈 수 있게 두거나, 넘어가도 이미 갈 수 있는 곳으로만 이어지게).
- **체크포인트**는 선택지가 갈라지는 분기점에 둔다. 되돌릴 수 없는 지점(문을 열거나 레이저 벽을 지난 직후 등)을 지난 직후처럼, 닿을 때까지의 선택으로 막혀 있을 가능성이 적은 곳이 좋다.
- v2용 `MapDesignRules.md`는 새로 쓰고, 규칙은 필요할 때마다 더한다.

### 9.6 정답 검증 도구 (나중에 만듦)

- 정답이 **존재하는지만** 확인한다(유일성 확인, 전체 나열, 더미 계산 없음).
- 입력은 씬과 `CustomStageData` JSON 둘 다다.
- 플레이어가 닿을 수 있는 곳은 플러드 필(BFS)로 구한다. 스페이스바 점프 연결은 계산하지 않는다.
- 길을 막는 것은 벽과 문 계열뿐이라 설치형 기물은 장애물로 다루지 않는다. 체크포인트마다 클리어할 수 있는지도 확인할지는 만들 때 정한다.
- 시간 제한은 두지 않는다.

## 10. 코드 구조

- 2026-11-01 개편으로 작동기 계열(`SubmittableObjectBase`), 소지 오브, 합성·제출 세션은 없앤다. 지금 색과 문·레이저 벽·목적지 판정의 코드 구조는 개편 코드 계획에서 정해 이 절과 코드 흐름 문서에 적는다.
- 색 값은 `OrbValue { int r, g, b }` 구조체이고 덧셈과 `==`를 구현한다. 채널 한도와 색 변환은 별도 함수로 둔다(이름은 개편 코드 계획에서 다시 볼 수 있음).
- **문 계열**은 스크립트가 열림 상태를 들고, 콜라이더와 막는 겉모습(문짝, 레이저 면)만 바꾼다(오브젝트를 통째로 끄지 않음).
- **기물 간 통신**은 두 가지로 나눈다(작동기 연결은 개편에서 없앰).
  - 맵 전체 상태(스냅샷 저장·복원, 재시작, 클리어)는 새 **맵 매니저**가 맡는다. 기물은 맵 매니저에 스스로 등록하고, '상태 내보내기/불러오기'로 저장·복원된다.
  - 소리, UI, HUD, 클리어 화면 같은 알림은 **EventBus**로 보낸다(받는 곳이 있는 이벤트만, 기물 상태 변화는 전용 이벤트).
- 맵 안의 진행은 맵 매니저가, 맵 사이의 전역 진행(클리어 기록 등)은 `GameManager`가 맡는다. `LevelManager`는 폐기하고 `ProgressManager`는 기능을 나눈다.
- 맵 재시작과 체크포인트 복귀는 두 경로로 나눈다. v1 `SceneRestarter`는 폐기하고 새로 쓴다.
- 그대로 두는 것: `GameState` enum, UIScene additive 로드 + Screen Space - Overlay Canvas, Framework.Core `SaveManager`(범용 JSON API로 v2 전용 파일 저장).
- **코드 이름**: 영어 PascalCase이고 파일 이름 = 클래스 이름이다. 추상 기반은 `Base`, 겉모습 컴포넌트는 `View`, 설정 애셋은 `Config`로 끝나고, 인터페이스는 `I`로 시작하며, 이벤트에는 Event를 붙이지 않는다. 같은 일은 같은 말로 부른다(색 원천 `ColorSource`, 문 `Door`). 기물 공통 기반은 `FixtureBase`다. 기획 용어와 코드 이름은 매핑 테이블로 잇는다(기물은 기물 분류 문서의 표, 그 밖은 코드 흐름 문서).
- **폴더**: `Assets/Scripts` 아래에 역할별 새 폴더(`Rules/`, `Map/`, `Fixtures/`와 계열별 하위 폴더, `NodeSystem/`)를 두고, v1을 참고해 새로 쓰는 기반 코드는 `Core/`, `Player/`, `UI/`, `Editor/`에 둔다(v1 폴더는 모두 지우고 새로 만듦). 테스트는 `Assets/Tests/EditMode/`에 둔다. 프리팹은 `Assets/Prefabs`(v1 `Prefebs`는 지우고 새로 만듦), 설정 애셋은 `Assets/Data`, 맵 씬은 `Assets/Scenes/Maps`, 부팅 씬 `Boot`와 `UIScene`은 `Assets/Scenes`에 둔다. v2 새 코드는 **`ColorMaze` 네임스페이스** 하나에 둔다(에디터 코드도 같음).
- **자동 테스트**는 코어 규칙(색 값 계산, 한도와 자르기, 문·레이저 벽·목적지 판정, 스냅샷 저장·복원)만 EditMode 테스트로 둔다. 그래서 코어 규칙은 MonoBehaviour와 떼어 순수 C#으로 쓰고 asmdef 하나(`ColorMaze.Assembly`, 테스트는 `ColorMaze.Assembly.Tests`)로 묶는다.
- **계층**: 코어 규칙(asmdef) ← 월드(맵 매니저, 플레이어, 기물, 노드 시스템) ← UI(UIScene). 월드와 UI는 기본 어셈블리에 두고, 이벤트와 인터페이스로만 만난다. v1 코드는 v2 코드를 쓰기 전에 지운다.
- 맵 매니저는 맵 씬마다 하나다. 기물은 공통 기반과 인터페이스(상호작용, 값 제공, 상태 저장)를 쓰고, 플레이어는 상호작용할 때 넘겨받는다. 체크포인트 스냅샷의 기물 상태는 기물마다 JSON 문자열로 담는다.
- 팝업은 UIScene의 팝업 호스트가 받고, 열려 있는 동안 게임플레이 입력만 잠근다(게임 상태가 아님). ESC는 뒤로 가기 스택이 받고, 닫을 것이 없을 때만 일시정지를 연다.
- 수치는 설정 애셋(게임 규칙, 기준 치수, 소리 연결)에 두고, 소리는 이벤트를 받는 소리 연결 한 곳에서 낸다.
- 맵 안 id, 시작 지점·목적지 개수, 요구 색의 값 규칙은 에디터 검사가 잡는다.

## 11. v1에서 지우거나 바꾸는 것

- **기물**: 컬러 필터는 문으로, 캔버스는 목적지로, 팔레트는 색 원천(흡수)으로 대체하고(구조는 새로 만듦), RGB 필터·버킷·컬러 체인저·스택 체인저는 삭제한다. v1 기물 클래스는 전부 지운다.
- **콘텐츠**: v1의 70개 스테이지는 전부 폐기하고 새로 만든다. v1 코드와 씬은 **전부**(맵 에디터, 메뉴, 기반 코드까지) v1 프리팹·v1 전용 애셋과 함께 **v2 코드를 쓰기 전에 먼저** 지운다(지울 것은 이름 앞에 '!!!!'). 이동·입력·설정·소리·부팅 같은 기반은 v1 코드(태그 `1.0.1`)를 참고해 새로 쓴다. 프로젝트 설정, 패키지, 하늘 상자·폰트·소리·UI 팩 같은 애셋은 남긴다.
- **UI·안내**: 마커 시스템(코드까지, v1 기물을 지울 때 함께), 스테이지 가이드(가이드 버튼 코드까지), 튜토리얼 3D 문구를 없앤다. 붓 뷰모델은 손 위 구(지금 색)로, 색 스택 HUD는 지금 색 HUD로 새로 만든다.
- **진행**: 스테이지/챕터 시스템과 해금 로직을 없애고 맵 선택 화면만 남긴다. v1의 모드 선택 패널도 지운다(맵 에디터로 가는 길은 에디터를 새로 만들 때 만듦).
- **맵 구조**: v1의 '필터가 바닥이 되어 떨어지고 왕복하는 구조'를 없앤다. 낙사 판정은 맵 밖으로 나간 경우의 안전망으로만 남긴다.
- **데이터**: v1 세이브(`save.json`, `stage_attempts.json`)는 v2를 처음 실행할 때 알리지 않고 지운다. `settings.json`은 남기고, 새 설정 코드도 같은 형식으로 읽는다. v1 유저 제작 맵은 호환하지 않는다(v2 맵은 다른 위치에 저장하고 v1 파일은 그대로 둠).

## 12. 예정과 미정

### 예정 (나중에 더할 계획)

- 수집 요소(클리어 화면의 수집률, 세는 것은 미정)
- 여러 칸을 쓰는 기물
- 인게임 맵 에디터(UGC)

### 미정 (개발하면서 정함)

- **수치**: 상호작용 거리, 이동 속도·가속, 카메라 눈높이, 점프 높이·거리, 기준 치수(벽 두께, 기둥 굵기, 문 폭·높이, 벽의 키, 코어 루프 9단계에서 정함)
- **기물**: 레이저 벽 색과 빼는 색에 0을 허용할지, 지날 수 있는지 미리 보이는 모양, 문·목적지가 요구 색을 보이는 모양, 저절로 닫히는 문 계열 종류의 세부(그런 종류를 만들 때)
- **연출·아트**
  - 흡수·체크포인트 효과의 세부, 문이 흔들리는 연출, 레이저 벽에서 색이 빠지는 연출
  - 상호작용 강조 색, 손 위 구의 입자 효과
  - 벽·기둥·바닥·천장 디자인
  - 라이팅, 블룸·톤매핑
  - BGM, 동시에 울리는 소리 개수
  - 3D 모델의 제작/구입 분담
  - 맵마다의 배경과 짧은 배경 설정의 내용
- **UI**: 폰트, 색 표시가 아닌 UI의 색 원칙, 지금 색 HUD의 자리와 모양, (0,0,0)일 때 손 위 구의 모양, 설정 메뉴의 나머지 항목
- **구현**: '처음부터'를 씬 재로드로 할지, 더할 그리기 최적화 기법, 정답 검증이 체크포인트마다 확인할지
- **나중 단계**: 인게임 맵 에디터(UGC)의 화면과 조작(에디터 새로 만들기 단계), 수집률이 세는 것(수집 요소를 넣을 때)
- 미정 항목과 아직 그리지 않은 그림(문·목적지 외형, 클리어 화면, 체크포인트, 예시 맵)은 상황에 따라 그림, 질문, 그 단계의 개발로 정한다.

## 13. 진행 방식

- **개발 순서**: **코어 루프 → 색 시스템 개편**(2026-11-01) **→ 진행 시스템**(체크포인트·'처음부터' → 저장·이어하기 → 메뉴 흐름: 맵 선택, 확인 창, 정식 클리어 화면) **→ 기물 늘리기** **→ 월드/아트 → 맵 제작**(정답 검증 도구와 v2 `MapDesignRules.md`를 먼저) **→ 에디터 새로 만들기**(v1 맵 에디터는 지우고 노드 방식에 맞춰 새로 만듦).
  - **월드/아트**는 이 순서를 기다리지 않고 별도의 아트 세션에서 지금부터 나란히 한다(위 순서는 코드 작업의 순서). 아트 세션은 복셀 제작만(MagicaVoxel·`.vox`·아트 문서, 만든 에셋을 `Assets` 폴더에 저장하는 데까지) 하고, Unity 작업(가져오기 설정, 프리팹·씬 연결)과 git은 메인 세션이 맡는다.
- **코어 루프**에서는 오브 값·소지 오브·뷰모델, 추출 오브젝트, 합성기와 합성 팝업, 작동기와 제출 팝업, 문과 레이저 벽, 목적지와 클리어 화면, 조준점 옆 값 표시와 인벤토리 창(흡수는 뒤), 벽 노드 시스템을 만든다(모양과 화면은 임시). 이 가운데 소지 오브·합성기·작동기와 제출 팝업·인벤토리 창은 2026-11-01 개편에서 없앤다.
  - 시험 맵은 노드로 벽을 세운 회색 시험 씬 하나다. 노드 편집 도구는 이 시험 맵을 만들 수 있는 만큼 먼저 만든다.
  - v1 코드·씬·프리팹은 전부 코어 루프를 시작할 때(0단계) 먼저 지운다. 코어 루프가 시험 맵에서 처음부터 끝까지 돌아가면 완성으로 보고 **알파 0.0.1**을 붙인다.
  - 체크포인트·저장·이어하기와 메뉴 흐름은 코어 루프 바로 다음(진행 시스템)에 만든다. 그사이에는 시험 씬을 에디터에서 바로 열어 확인한다(에디터 메뉴의 'Play: 열린 맵에서 바로 시작'을 켜면 부팅 씬 `Boot`에서 부팅한 뒤 열린 씬을 바로 불러옴). 메인 메뉴가 없으므로 코어 루프 동안 일시정지 메뉴는 '계속·처음부터·종료'만 두고, 임시 클리어 화면도 '다시 하기·종료'만 둔다.
- **코드 흐름 설계**: 코어 루프의 코드 흐름은 `Docs/v2 코드 흐름 설계.md`로 동의를 받았다. 코드 이름과 폴더 이름도 정했다(`Docs/v2 코드 이름과 폴더 제안.txt`). 코어 루프는 v1 지우기(0단계) 뒤 9단계로 만든다: 코어 규칙과 테스트 → 개발 기반 → 벽 노드 시스템 → 추출 → 합성 → 작동기와 문 계열 → 목적지와 클리어 → 값 표시와 인벤토리 창 → 시험 맵 다듬기. 단계마다 Play 모드에서 확인할 것을 정리해 사용자가 테스트한다.
- **일하는 방식**: 단계마다 만들 파일과 씬 작업 목록을 먼저 보이고 동의를 받는다. 코드를 쓰고, 씬·프리팹·애셋은 **Claude가 Unity CLI로 열린 에디터에서 직접** 만든다. 컴파일과 EditMode 테스트는 Claude가 CLI로 확인하고, Play 모드 확인은 목록을 받아 **사용자가** 한다. 통과하면 커밋할지 묻는다.
- **브랜치**: v2 작업은 `main` 브랜치에 바로 커밋한다(따로 브랜치를 두지 않음). v1은 태그 `1.0.0`, `1.0.1`에 남아 있다. 안정되면 태그로 버전을 붙인다.
- **버전**은 알파 0.0.1부터 시작한다. **빌드 대상**은 일단 윈도우만이다.
- 개인 습작이라 재미 검증용 프로토타입 단계는 따로 두지 않는다.
- 설계 결정이 나면 결정 로그와 이 문서를 함께 고친다.
