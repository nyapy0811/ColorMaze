Q454. [핵심] 색이 같고 크기만 다른 값의 처리 (정규화 RGB + 혼합색만의 결과)

2단계 2차 대답 Q262에서 오브젝트 색은 값의 비율을 정규화한 RGB로 칠하고(밝기는 오브젝트마다 설정), 표현은 혼합색만 쓰기로 했습니다. 그러면 비율이 같고 크기만 다른 값은 같은 색으로 보입니다. 예를 들어 (1,0,0), (2,0,0), (5,0,0)은 모두 같은 빨강이고 (1,0,1)과 (2,0,2)도 같은 자주색입니다. 그 결과 (1) 추출 전(오브젝트)에도 추출 후(뷰모델, 합성·제출 팝업)에도 비율만 보이고 크기는 보이지 않아, 1단계 Q141의 "추출한 뒤에는 값을 확인할 수 있다"와 맞지 않습니다. (2) 합성 미리보기에서 (1,0,0) + (1,0,0) = (2,0,0)을 해도 색이 바뀌지 않습니다. (3) 정확한 값은 제출에 실패했을 때의 안내(필요한 값과 낸 값, 2단계 Q444)로만 알 수 있습니다. 판정은 지금 값이 정확히 같아야 통과하므로(1차 Q6, 1단계 Q144), 같은 색으로 보이는 오브를 냈는데 거부되는 일이 생깁니다. 이 결과가 의도한 것인지 확인하려는 질문입니다.

  [오브젝트별 밝기의 뜻]
    - 아트용일 뿐 값과 무관 (값의 크기는 색으로 드러나지 않음)
    - 값의 크기를 밝기로 나타내되, 크기마다 쓸 밝기는 오브젝트마다 맵 제작자가 정함
    - 기타
  [색이 같고 크기만 다른 오브를 어떻게 다룰지]
    - 크기는 몰라도 됨: 판정은 지금처럼 값이 정확히 같아야 하고(1단계 Q144), 정확한 값은 제출 실패 안내로만 알 수 있음 (1단계 Q141의 "추출한 뒤 값 확인"은 취소). 필요하면 맵 설계로 보완 (예: 추출 오브젝트를 한 채널 값이 1인 오브젝트 위주로 두어 개수로 크기를 셀 수 있게)
    - 합성·제출 팝업 안에서만 숫자를 보임 (월드와 뷰모델은 혼합색만, 1단계 Q141 유지)
    - 밝기로 충분함 (위에서 '값의 크기를 밝기로 나타냄'을 고른 경우)
    - 판정을 비율(색) 기준으로 바꿈: 색이 같으면 통과 (예: 빨강 목표에 (1,0,0)도 (2,0,0)도 통과). 1차 Q6과 1단계 Q144의 '완전 일치'를 '비율 일치'로 바꾸며, 크기는 채널 한도에만 영향
    - 기타

이유: 이 답에 따라 1단계 Q141(또는 판정 기준) 결정을 바꿀지가 정해지고, 목표 라벨(3단계 Q224), 색각 이상 대응(5단계 Q408), 한도 표시(6단계 Q412), 맵 설계 규칙(목표 값과 오브젝트 구성)이 달라집니다.

답:아트용일 뿐 값과 무관(오브젝트 바라보면 값이 공중에 떠서 확인가능하게), 오브는 항상 최대 밝기로 (구체적 값은 ui와 추가 hud로 확인 가능하게)

Q455. [보통] 세 채널이 같은 값((1,1,1) 등)의 오브젝트와 목표

정규화 RGB(2단계 2차 대답 Q262)에서는 (1,1,1), (2,2,2)처럼 세 채널이 같은 값이 흰색이 되고, 오브젝트별 밝기에 따라 회색으로도 보입니다. 월드는 무채색(테스트 버전은 흑백 머티리얼, 1차 Q32)이고 추출한 오브젝트도 무채색으로 바뀌므로(1차 Q18), 이런 오브젝트는 벽이나 이미 추출한 오브젝트와 구분하기 어렵습니다. 합성으로는 (1,1,0) + (0,0,1) = (1,1,1)처럼 언제든 생길 수 있습니다.

  - 추출 오브젝트와 목표에는 쓰지 않음 (맵 제작 규칙으로 금지, 합성 결과로 생기는 것은 허용)
  - 허용하고 발광 등 다른 표현으로 구분 (4단계 Q196, 5단계 Q396)
  - 기타

이유: 맵 설계 규칙 문서(3단계 Q363)와 정답 검증 도구(3단계 Q415)에 넣을 규칙인지, 표현으로 풀 문제인지가 갈립니다.

답:1

Q456. [사소] 맵 선택 화면과 클리어 화면의 세부

2단계 2차 대답 Q447에서 맵 선택 화면의 목록 순서를 '다음 맵' 순서로 정했고, Q449에서 '처음부터'를 누르면 저장된 체크포인트를 지우기로 했습니다. 이와 이어지는 작은 동작입니다.

  [마지막 맵의 '다음 맵' 버튼]
    - 비활성(회색)
    - 숨김
    - 맵 선택 화면으로 가는 버튼으로 바뀜
    - 기타
  [체크포인트가 저장된 맵을 맵 선택 화면에서 '이어하기'가 아니라 처음부터 시작할 때]
    - 확인 창을 띄우고, 시작하면 그 맵의 체크포인트 기록을 지움 (일시정지 메뉴 '처음부터'와 같은 규칙, 2단계 2차 대답 Q449, Q453)
    - 확인 창 없이 시작하고 기록을 지움
    - 기록을 남겨 둠 (새로 시작한 판에서 첫 체크포인트에 닿으면 덮어씀)
    - 기타

이유: 클리어 화면과 맵 선택 화면의 버튼 동작을 만들 때 필요합니다.

Q457. [보통] v1 세이브 파일 제거의 범위와 방식

2단계 2차 대답 Q452에서 v2 저장 데이터는 ColorMaze 전용 클래스로 별도 파일에 저장하고, v1 때의 세이브 파일은 전부 지우기로 했습니다(백업 없이 지우는 것으로 이해했습니다). v1이 플레이어 PC(Application.persistentDataPath)에 남기는 파일은 아래와 같습니다. 유저 제작 맵(CustomMap_*.json)은 1차 Q44에서 그대로 보존하기로 했으므로 지우지 않는 것으로 두었습니다.

  [지울 파일] (여러 개 골라도 됨)
    - save.json (v1 진행: 스테이지 클리어 기록, 챕터 해금)
    - stage_attempts.json (v1 스테이지별 시도 횟수)
    - settings.json (설정: 음량, 해상도, 마우스 감도 등. 지우면 v2 첫 실행 때 기본값으로 돌아감)
  [지우는 방식]
    - v2를 처음 실행할 때 알리지 않고 자동으로 지움
    - v2를 처음 실행할 때 "이전 버전의 진행 기록을 초기화했습니다" 같은 안내를 보여 주고 지움
    - v2를 처음 실행할 때 지울지 묻고, 확인을 누르면 지움
    - 기타

이유: 지울 파일과 처리 방식이 정해져야 v2 첫 실행 처리를 만들 수 있습니다. 설정 파일을 남길지는 6단계 Q316(설정 저장 방식), 5단계 Q237(설정을 저장 파일에 합칠지)과 이어집니다. 4단계 Q311(백업)과 Q315(경고 메시지)는 이 질문으로 합쳤습니다.

Q221. [핵심] 소지 오브 HUD의 위치·형태·값 표시
(통합 질문: Q221 + Q222 + Q223 + Q242 + Q245)

※ 1단계 답변 반영: 정해진 것: 뷰모델이 소지 오브 HUD를 겸하고(2단계 2차 대답 Q445), 손 없이 모든 소지 오브를 화면 코너에 항상 띄웁니다(2단계 Q178). 값은 혼합색만으로 보입니다(2단계 2차 대답 Q262, 팝업에 숫자를 둘지는 3단계 Q454). 따라서 [값 표시]는 '슬롯 색만 표시'로 정해졌고, [형태]의 원형 선택기와 요약 정보만은 해당 없습니다. 남은 것: 어느 코너에 둘지와 오브 N개를 어떻게 늘어놓을지(한 줄 / 격자 / 세로 목록)입니다.

소지 오브 HUD(상시 표시)를 (1) 화면 어디에 배치하고, (2) 슬롯 N개를 어떤 형태로 그리며, (3) 각 오브의 값(R,G,B)을 어떻게 표시하는가? (1차 Q35에서 '소지 오브 HUD(상시 표시)로 대체'까지 정해졌습니다.)

  [위치]
    - 좌상단 (v1 ColorStackHUD와 유사)
    - 우상단
    - 하단 중앙
    - 좌측 세로 / 우측 코너 등 (직접 기재)
  [형태]
    - 색 사각형 N개를 한 줄로 나열
    - 2×3 또는 3×3 그리드 (인벤토리 스타일)
    - 슬롯 번호가 붙은 세로 목록 (선택된 것 강조)
    - 원형 선택기 (마우스 휠 선택)
    - 현재 오브를 크게 보이는 3D 미니 렌더
    - 요약 정보만 (총량/색별 개수)
  [값 표시]
    - 슬롯 색만 표시 (값은 선택 UI에서만)
    - 슬롯 아래/옆에 '(R,G,B)' 텍스트
    - 마우스 호버 시 툴팁
    - 숫자 라벨 + 색 둘 다

이유: HUD 크기와 시각 계층, 조준 UI와의 충돌 여부, 플레이어가 한눈에 파악하는 정보량, 슬롯 개수 제한이 모두 여기에 달려 있다. 플레이어가 오브 조합을 계획하려면 값을 알아야 한다.
참고 코드: Assets/Scripts/UI/ColorStackHUD.cs

답:우하단, 오브들을 3d 오브젝트로 보여줌, 기본적으로 오브 색만 표시(tab 등으로 추가 내용 확인할때 같이 확인 가능)

Q224. [핵심] 목표 색 라벨의 위치·포맷·폰트
(통합 질문: Q224 + Q246 + Q252 + Q402)

※ 1단계 답변 반영: 참고: 제출에 실패하면 필요한 값과 낸 값을 모두 보여 줍니다(2단계 Q444). 오브는 혼합색만 보이고 색은 값의 비율만 나타내서, (1,0,0)과 (2,0,0)처럼 크기만 다른 값은 같은 색입니다(2단계 2차 대답 Q262). 목표 라벨에 숫자를 보이면 목표 값은 알지만 소지 오브의 값은 모르는 상태가 됩니다. 값의 크기를 알 수 있게 할지(3단계 Q454)와 함께 정하면 됩니다.

문/목적지/레이저 작동기의 목표 색(필요한 오브 색) 라벨을 (1) 어디에, (2) 어떤 형식으로, (3) 어떤 크기/폰트로 표시하는가? (1차 Q36은 '라벨을 붙이는 방식을 쓸 가능성이 높다'는 임시 결정입니다. 라벨을 쓰지 않는다면 그 사실도 알려 주세요.)

  [위치]
    - 기물 위 빌보드 라벨 (v1 ColorCanvas처럼 플레이어를 바라봄)
    - 기물 정면/옆에 고정된 라벨 (회전하지 않음)
    - 기물에 색으로만 표시 (텍스트 라벨 없음)
    - 조준했을 때만 표시
    - 제출 UI가 열릴 때만 팝업으로 표시
  [형식]
    - 숫자 라벨 'R:1 G:2 B:3' 형태
    - 간단한 텍스트 (예: '빨강1 파랑2')
    - 색상 칩/아이콘
    - 숫자 + 색상 칩 함께
  [크기/폰트]
    - v1 TextMeshPro 기본값 유지
    - 더 크거나 굵은 폰트 (가독성 우선)
    - 한글 전용 폰트 지정

이유: 플레이어가 목표를 명확히 인지해야 한다. 위치가 정해지지 않으면 기물별로 라벨 위치 계산 로직을 중복 구현하게 되며, 1차 Q36이 '가능성 높음' 수준으로만 정해져 있어 최종 결정이 필요하다.
참고 코드: Assets/Scripts/UI/CellGroupLabel.cs, Assets/Scripts/MapObjects/ColorCanvas.cs, Assets/Scripts/MapObjects/MapObjectBase.cs

Q393. [핵심] 무채색 월드 구현 방식

테스트 버전은 머티리얼 흑백이라고 했는데, 최종 구현에서 무채색 월드를 어떻게 표현할 것인가? 그레이스케일 필터/포스트프로세싱, 새로운 셰이더, 아니면 월드 머티리얼을 단색으로 재제작하는 방식 중 어느 것인가?

  - 그레이스케일 포스트프로세싱 필터
  - 색상 채도 제거 셰이더로 모든 월드 머티리얼 감싸기
  - 월드 머티리얼 재제작(회색/검은색)
  - 색상 정보를 다른 채널(노멀맵 등)로 인코딩

Q394. [핵심] 오브 3D 모델 기본 형태

오브의 3D 모델을 어떤 기본 형태로 제작할 것인가? 구(Sphere), 정육면체, 별 모양, 커스텀 유기형 등 어느 것을 베이스로 할 것인가?

  - 구(Sphere) - 단순하고 회전 불명확
  - 정육면체 - 직관적이고 각 면에 채널 표시 가능
  - 별 모양/크리스탈 - 독특한 실루엣
  - 유기형 커스텀 모양

이유: 오브 모델의 기본 형태가 정해지지 않으면 아트 제작 파이프라인과 에셋 구입 방향을 결정할 수 없다.

Q395. [핵심] 에셋 제작 vs 구입 분담

오브, 문, 합성기, 배경 메시 등을 직접 제작할 것인가, 에셋스토어에서 구입할 것인가? 카테고리별 전략은?

  - 핵심(오브, 문) 직제작 + 배경은 에셋
  - 모두 구입 - 빠른 프로토타입
  - 모두 직제작 - 커스텀 일관성
  - 하이브리드 - 에셋을 개조해 사용

이유: 에셋 전략이 정해지지 않으면 프로젝트 일정과 비용, 스타일 일관성을 예측할 수 없다.
