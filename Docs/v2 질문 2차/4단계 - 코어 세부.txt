Q464. [핵심] 노드 시스템에서 문의 형태 확인

3단계 2차 대답 Q460의 [문의 형태]에 "벽 구간 사이에 문 설치"라고 답하셨습니다. 이 말이 두 가지로 읽혀서 확인하려는 질문입니다. 벽 구간은 0.25유닛 벽 모듈을 반복해 채우고, 모든 노드에 기둥을 두며, 0.25 미만으로 남는 길이는 기둥이 가립니다(3단계 2차 대답 Q459).

  [문의 형태]
    - 노드 사이 구간 하나가 통째로 문 (문 양쪽 끝에 노드와 기둥이 있고, 그 양옆 구간은 일반 벽)
    - 벽 구간 중간에 정해진 폭의 문을 끼움 (구간 위의 위치만 지정하고, 그 자리의 벽 모듈은 자동으로 비움)
    - 기타
  [중간에 끼우는 경우의 폭과 위치] (두 번째를 고른 경우)
    - 문 폭은 하나로 고정, 위치는 0.25유닛 단위로 맞춤 (문 양옆이 벽 모듈 경계와 맞음)
    - 문 폭을 문마다 정할 수 있음 (0.25유닛의 배수)
    - 기타
  [대각선 구간의 문]
    - 대각선 구간에도 문을 둘 수 있음
    - 문은 가로·세로(축 방향) 구간에만 둠
    - 기타

구간 하나를 통째로 문으로 쓰면 데이터는 벽 항목의 종류를 '문'으로 두는 것으로 끝납니다(3단계 2차 대답 Q321). 대신 문 폭이 노드 사이 거리라 문마다 다를 수 있고, 대각선 구간이면 정수도 아닙니다(예: (1,1)과 (2,2) 사이는 약 1.41유닛). 그래서 문 프리팹을 구간 길이에 맞게 늘리거나 길이별 문을 만들어야 합니다. 중간에 끼우면 문 프리팹 하나를 그대로 쓰지만, 벽 항목에 '문의 위치' 필드가 더해지고 끼울 위치를 정하는 편집 기능이 필요합니다. 레이저 벽은 노드 사이 구간 하나로 정했습니다(3단계 2차 대답 Q460).

답:벽 구간 중간에 정해진 폭의 문을 끼움,문 폭은 하나로 고정, 위치는 0.25유닛 단위로 맞춤대각선 구간에도 문을 둘 수 있음

Q465. [보통] 레이저 벽 구간을 채우는 방법

레이저 벽은 노드 사이 구간 하나이고(3단계 2차 대답 Q460), 콜라이더는 레이저 벽 전체를 MeshCollider 하나로 만들기로 했습니다(2단계 Q261). 일반 벽은 0.25유닛 모듈을 반복하고 0.25 미만으로 남는 길이는 노드 기둥이 가립니다(3단계 2차 대답 Q459). 레이저 벽의 겉모습과 콜라이더를 어떻게 채울지 정해야 합니다.

  - 일반 벽처럼 0.25유닛 레이저 모듈을 반복하고, 콜라이더만 구간 전체에 하나 (남는 길이는 기둥이 가림)
  - 레이저 프리팹 하나를 구간 길이에 맞게 늘림 (겉모습과 콜라이더 모두 하나)
  - 기타

레이저는 빛줄기나 반투명 면이라 늘려도 늘어나 보이는 문제가 벽보다 적습니다. 모듈 방식이면 일반 벽과 같은 배치 코드를 쓰고, 늘리는 방식이면 구간마다 오브젝트가 하나라 켜고 끄기와 콜라이더가 단순합니다. 레이저 벽의 시각 표현은 5단계 Q397, 켜짐·꺼짐 표현은 5단계 Q375에서 묻습니다.

답:레이저 프리팹 하나를 구간 길이에 맞게 늘림 (겉모습과 콜라이더 모두 하나)

Q466. [보통] 기물 첫 만남 팝업과 기물 리스트의 세부

3단계 2차 대답 Q463에서 새 기물을 처음 볼 때 팝업을 띄우고, 본 기록을 남겨 다시 띄우지 않으며, 메인 메뉴의 '기물 리스트 모음'에서 다시 볼 수 있게 했습니다. 이를 만들 때 정할 세부입니다. 특히 저장은 체크포인트에 닿을 때만 하기로 했으므로(2단계 Q294), 본 기록도 그때 저장하면 체크포인트에 닿기 전에 게임을 끈 경우 같은 팝업이 다시 뜹니다.

  [처음 본다의 기준]
    - 화면(시야)에 처음 들어올 때
    - 처음 조준할 때 (거리와 상관없이)
    - 상호작용 거리 안에서 처음 조준할 때 (값 표시가 뜨는 조건과 같음, 3단계 2차 대답 Q461)
    - 처음 상호작용(클릭)할 때
    - 기타
  [본 기록을 저장하는 때]
    - 팝업을 닫는 즉시 저장 (체크포인트에서만 저장하는 규칙의 예외)
    - 체크포인트에 닿을 때 함께 저장 (그 전에 게임을 끄면 다시 뜰 수 있음)
    - 기타
  [본 기록을 지우는 때] (여러 개 골라도 됨)
    - 지우지 않음 ('처음부터'나 클리어로 체크포인트 기록을 지워도 유지)
    - 설정 화면의 저장 초기화 때 함께 지움
    - 기타
  [기물 리스트에서 아직 못 본 기물]
    - 숨김 (본 기물만 목록에 나옴)
    - 잠김 표시 (자리는 보이고 내용은 가림)
    - 모두 보임
    - 기타
  [기물 리스트로 들어가는 곳]
    - 메인 메뉴에 버튼 추가
    - 설정 화면 안
    - 기타

본 기록은 맵과 상관없는 전역 기록으로 v2 저장 파일(2단계 2차 대답 Q452)에 들어갑니다. 팝업에 무엇을 담을지(글, 그림, 짧은 영상)는 내용을 만들 때 정해도 됩니다. 팝업이 떠 있는 동안은 합성·제출 팝업처럼 이동과 시점 회전을 막는 것으로 두었습니다(2단계 Q176).

답:상호작용 거리 안에서 처음 조준할 때 (값 표시가 뜨는 조건과 같음, 3단계 2차 대답 Q461)

Q132. 합성 성공 연출과 효과음
(통합 질문: Q132 + Q233)

합성기에서 여러 오브가 합쳐져 결과 오브가 생길 때 시각/소리 연출은 어느 수준인가? (1차 Q13: 합성에 시간은 필요 없고 연출과 소리는 필요)

  - 입자 병합 애니메이션 + 2층 음향 (합성음 + 성공음)
  - 빠른 플래시 + 단일 '딩' 음
  - 결과 오브 생성 위치에서 버스트 입자만
  - UI 반짝임 + 무음
  - 진행 소리 (점진적 건설음)
  - 음향 없음 (시각 효과만)

이유: 합성의 성공감을 전달하려면 연출 규모와 UX 흐름(합성 후 결과 표시까지)이 함께 정해져야 한다.

Q133. 합성기 UI 인터랙션 표현

※ 1단계 답변 반영: 정해진 것: 합성기 UI는 슬롯의 오브를 클릭해 선택하면 결과 오브가 실시간 미리보기로 나오고, 결과 오브를 클릭하면 합성이 실행됩니다(드래그나 별도 확인 버튼 없음, 1단계 Q117, Q121). 1개 이상 선택하면 합성할 수 있고, 지금 선택에 더하면 한도를 넘게 되는 오브는 처음부터 회색(선택 불가)으로 표시됩니다(1단계 2차 대답 Q441, Q442). 남은 것: 각 동작에 붙는 애니메이션과 소리입니다.

합성기와 상호작용할 때 시각적 피드백은? (오브 드래그, 확인 버튼, 결과 미리보기 영역 등) 어떤 애니메이션과 소리를 동반할 것인가?

  - 오브 드래그 + 결과 실시간 미리보기 + 각 상호작용 마다 틱음
  - 오브 선택 후 확인 버튼 클릭(2단계) + 버튼 클릭음
  - 제출식 - 오브 떨어뜨림 후 자동 합성 + 처리음
  - 터치 기반 - 손가락 제스처 + 터치음

이유: 인터랙션 피드백이 명확하지 않으면 합성 메커니즘을 이해하기 어렵다.
참고 코드: Assets/Scripts/Core/GameAudio.cs

    해소: 1차 Q44에서 정해졌습니다: 메인 메뉴의 '맵 에디터'와 '커스텀 맵' 버튼은 숨깁니다(세 번째 선택지). 기존 커스텀 맵 파일은 그대로 보존합니다.
  - Q272. 오브 제출 시 동시성 문제
    질문: 플레이어가 합성기에서 오브를 선택해 동시에 여러 제출 지점(문, 목적지, 작동기)을 조준할 수 있습니다. 오브를 제출하려 할 때 '이 오브를 누가 받을 것인가'를 어떻게 결정합니까? 우선순위(가장 가까운 것, 조준점 정중앙)를 정의해야 합니까?
    해소: 1단계 Q143에서 제출 UI는 조준(카메라 중심) + 좌클릭으로 열기로 정했습니다. v1처럼 화면 중앙 레이캐스트에 처음 맞은 기물 하나만 대상이 되므로 여러 제출 지점이 동시에 대상이 되지 않고, 오브는 그 기물의 팝업에서 골라 냅니다.
  - Q281. 여러 기물을 동시에 조준할 때의 우선순위
    질문: 오브를 제출하려는데 문과 목적지가 조준 범위 안에 둘 다 있으면 어디에 제출되는가? (1) 가장 가까운 것, (2) 조준점 중앙, (3) 플레이어 선택, (4) 기물 종류 우선순위?
    해소: 1단계 Q143에서 조준(카메라 중심) + 좌클릭으로 정했습니다. 화면 중앙 레이캐스트에 처음 맞은 기물 하나만 대상이 되므로 문과 목적지가 동시에 대상이 되는 일이 없습니다. 같은 내용의 Q272도 같은 이유로 해소했습니다.

  - Q306. 일시정지 메뉴의 '다시하기' 버튼
    질문: v1의 '가이드 버튼' 제거 후, '다시하기'는 어떻게 구현할 건지? SceneRestarter를 그대로 쓸 건지?

  - Q310. 문 상태 저장
    질문: 문이 열림/닫힘 상태를 저장할 건지? 문에 제출된 오브도 저장할 건지?
    해소: 2단계 Q260에서 체크포인트 스냅샷에 제출 상태(어느 문/작동기에 어떤 오브가 있는지)를 넣기로 했습니다. 문의 개폐는 문이 오브를 들고 있는지로 정해지므로(오브가 없으면 닫힘, 2단계 Q259) 레이저 벽처럼 따로 저장하지 않습니다.
  - Q278. 제출한 오브의 사용 여부 추적
    질문: v1은 MapObjectUsed 이벤트로 '기물이 사용됨'을 추적해 스테이지 가이드에 씁니다. v2에서 오브를 제출할 때도 유사하게 '이 오브가 사용됨'을 기록할 것인지, 아니면 '제출 성공'만 기록할 것인지?
    해소: 2단계 2차 대답 Q267에서 받는 곳(소리, UI, HUD, 저장)이 있는 이벤트만 만들기로 했습니다. 사용 기록을 받던 스테이지 가이드는 제거되므로(1차 Q38) 제출한 오브의 사용 기록은 따로 남기지 않고, 소리나 HUD처럼 받는 곳이 있는 제출 이벤트만 만듭니다. 나중에 힌트나 리플레이 기능을 만들면 그때 추가합니다.
