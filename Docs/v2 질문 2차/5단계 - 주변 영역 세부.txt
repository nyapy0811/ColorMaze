Q228. 빈 슬롯 표현

※ 1단계 답변 반영: 정해진 것: 오브를 제출하면 그 칸은 빈칸으로 남고 다른 오브는 자리를 유지합니다(1단계 Q142). 따라서 '완전히 빠지는 것(슬롯이 축약됨)' 선택지는 해당 없습니다. 소지 오브는 뷰모델이 화면 우하단에 3D 오브젝트로 보이고(2단계 2차 대답 Q445, 3단계 Q221), 손이 보이며 오브는 오른손 위에 모여 떠 있습니다(오버워치 시그마 느낌, 그림 확인 채팅, 그림 5). 남은 것: 손 위에 떠 있는 오브들 사이에서 빈칸을 어떻게 보일지(예: 흐린 구, 빈 자리만 남김)와, 합성·제출 팝업의 소지 오브 목록에서 빈칸을 어떻게 보일지입니다.

비어있는 슬롯을 어떻게 구분하는가? 투명한 칸인가, 아니면 '(비어있음)' 같은 텍스트인가?

  - 회색 또는 투명 칸으로 표시
  - '—' 또는 '(비어있음)' 텍스트
  - 완전히 빠지는 것 (슬롯이 축약됨)

이유: 플레이어가 소지 상태를 직관적으로 파악해야 한다.

답: hud 에서 빈 슬롯을 굳이 나타낼 필요가 없다. 최대 소지 개수 - 현재 소지 개수 = 빈칸 수 일테니

Q229. 슬롯이 가득 찼을 때의 피드백 표현
(통합 질문: Q229 + Q401)

※ 1단계 답변 반영: 정해진 것: 슬롯이 가득 차면 추출 불가입니다(1단계 Q148). 조준점은 색이 바뀌지 않으므로(4단계 Q193) 첫 번째 선택지(조준점 빨간색)는 해당 없습니다. 남은 것: 그 상황을 플레이어에게 어떻게 알리는가(문구, 소리 등)입니다.

슬롯이 가득 찬 상태에서 새 오브 추출을 시도했을 때 어떤 피드백을 주는가? (바로 앞 '슬롯이 가득 찬 상태에서의 추출 동작'에서 '추출 불가'로 정해지면 이 피드백이 필요합니다.)

  - 조준점이 빨간색으로 변함 (상호작용 불가 표시)
  - '슬롯이 가득 찼습니다' 팝업/텍스트
  - 거부음(부저)만
  - 상호작용 자체를 막음 (하이라이트·레이캐스트 제외)
  - HUD에서 오버플로우를 시각화

이유: 슬롯 가득 참 상태를 명확히 전달해야 플레이어가 기존 오브를 제출/합성해야 함을 알 수 있다.
참고 코드: Assets/Scripts/Core/GameAudio.cs

Q231. 뷰모델 색상 표시

※ 1단계 답변 반영: 정해진 것: 뷰모델은 모든 소지 오브를 화면 우하단에 3D 오브젝트로 항상 띄우고 소지 오브 HUD를 겸합니다(2단계 Q178, 2단계 2차 대답 Q445, 3단계 Q221). 손이 보이고 오브는 오른손 위에 떠 있습니다(그림 확인 채팅, 그림 5). 오브 모델은 일단 구이고(3단계 Q394), 색은 값의 비율을 정규화한 RGB를 항상 최대 밝기로 씁니다(2단계 2차 대답 Q262, 3단계 Q454). 따라서 '무채색 기본 모델만 표시' 선택지는 해당 없습니다. 남은 것: 머티리얼 색을 실행 중에 바꿀지, 색 조합마다 프리팹을 둘지입니다.

뷰모델 오브의 색을 실시간으로 렌더하는가 (v1 Brush처럼), 아니면 고정 모델만 표시하는가?

  - 오브 색을 동적으로 렌더 (머티리얼 색상 변경)
  - 색 프리팹 여러 개 (각 색/조합마다 모델 다름)
  - 무채색 기본 모델만 표시

이유: 아트 리소스와 렌더링 성능이 결정된다.

답:오브 색을 동적으로 렌더

Q232. 오브 추출 연출과 효과음
(통합 질문: Q232 + Q213 + Q218)

※ 1단계 답변 반영: 정해진 것: 추출할 때 오른손을 뻗어 오브젝트의 색을 빨아들이는 연출입니다(오버워치 모이라 느낌, 그림 확인 채팅, 그림 5). 세 번째 선택지(오브젝트 → 손 수집 애니메이션)에 가깝습니다. 남은 것: 연출 길이, 효과음, 추출 직후 팝업을 자동으로 열지입니다.

오브젝트에서 오브를 추출할 때 연출은 어느 수준인가? (1차 Q18: 추출은 즉시 이루어지며 짧은 추출 효과 정도는 가능) 소리의 길이/유무와, 추출 직후 자동으로 팝업을 열지도 정해 주세요.

  [연출]
    - 즉시 획득 (이펙트 없음)
    - 즉시 추출 + 짧은 이펙트/소리
    - 짧은 수집 애니메이션 (오브젝트→손, 0.5~1초) + 소리
    - 입자 이펙트 + 소리 + 화면 진동
    - 추출 후 자동으로 팝업을 열어 바로 합성/제출 가능
  [효과음]
    - 짧은 효과음 (200ms 이하)
    - 긴 효과음 (500ms 이상)
    - 음향 없음

이유: 추출 연출의 길이가 게임의 템포와 반복 상호작용의 쾌감, 전체 톤을 결정한다. 추출은 가장 자주 반복되는 행동이다.

답:짧은 수집 애니메이션 (오브젝트→손, 0.5~1초) + 이펙트/소리

Q236. UI 폰트의 선택
(통합 질문: Q236 + Q244)

게임의 모든 텍스트 UI(라벨, HUD, 메뉴)에 쓸 한글 폰트와 폰트 스타일은 무엇인가?

  - TextMeshPro 기본 폰트 + 한글 추가 애셋 (현재 방식 유지)
  - 특정 한글 폰트 지정 (이름 기재)
  - 고정폭 모노스페이스 (숫자 읽기 좋음)
  - 기하학 산세리프 (현대적)
  - 커스텀 폰트 설계 또는 구입
  - 아직 정하지 않음 (나중에 결정)

이유: 폰트가 정해지지 않으면 UI 시안을 확정할 수 없고, 한글 가독성과 시각적 통일감, 번역/다국어 대응에도 영향을 준다.

답:아직 정하지 않음 (나중에 결정)

Q240. 성공/실패 알림 위치

※ 1단계 답변 반영: 참고: 제출 실패는 팝업 안에서 클릭한 오브가 흔들리는 것으로 알리고, 요구 값은 팝업에 늘 보이며 낸 오브의 값은 마우스를 올리면 뜨는 값 상자로 봅니다(그림 확인 채팅, 그림 4). 팝업은 ESC로 닫습니다. 이 질문은 그 밖의 짧은 알림(예: 슬롯이 가득 차 추출할 수 없을 때, 5단계 Q229)을 화면 어디에 띄울지입니다.

제출 실패 같은 짧은 피드백 메시지를 화면의 어디에 표시하는가?

  - 화면 중앙 상단
  - 화면 중앙
  - 우상단 (토스트 스타일)
  - 조준점 주변

이유: UI 배치와 가독성이 결정된다.

Q247. 클리어 화면의 정보 표시 범위

※ 1단계 답변 반영: 정해진 것: 클리어 화면은 새로 디자인하고 클리어 시간을 보여 줍니다(4단계 Q199, Q200). 맵별 시도 횟수는 기록하지 않으므로(4단계 Q305) 두 번째 선택지(시간 + 시도 횟수)는 해당 없습니다. 시간은 이어하기로 나눠 해도 합쳐서 재고, 맵별 최고 기록을 저장해 맵 선택 화면에도 보입니다(4단계 2차 대답 Q468). 남은 것: 시간 말고 함께 보일 정보입니다. 모든 오브를 찾는 수집 요소를 추가할 예정이므로(3단계 Q362) 수집률을 보일지도 함께 적어 주세요.

Q62에서 '클리어 화면 디자인'과 '클리어 시간 추적'을 묻긴 했는데, v1처럼 '클리어 시간만' 표시하는가, 아니면 (1) 시도 횟수, (2) 수집률, (3) 기타 통계도 함께 표시하는가?

  - 시간만 표시 (v1 방식)
  - 시간 + 시도 횟수
  - 시간 + 통계 대시보드
  - 최소 정보 (클리어만 확인)

이유: 스테이지/챕터 시스템이 비활성화된 상태에서 클리어 후 플레이 피드백의 수준을 정해야 한다.
참고 코드: Q62, Q63, Q64

답:시간 + 통계 대시보드

Q327. 벽 높이 가변성

※ 1단계 답변 반영: 참고: 노드 좌표에는 높이(y)를 넣어 두기로 해서(3단계 2차 대답 Q321) 노드마다 높이가 달라도 데이터에 담을 수 있습니다. 벽은 메시를 만들지 않고 0.25유닛 벽 모듈을 반복해 놓고 모든 노드에 기둥을 두므로(3단계 Q323, 3단계 2차 대답 Q459), 이유의 '메시 생성 로직'은 '모듈 배치'로 읽어 주세요. 높이가 가변이면 모듈과 기둥을 높이에 맞게 늘리거나 높이별 모듈이 필요합니다.

벽의 높이가 고정된 상수인가, 아니면 노드마다 설정 가능한가? 높이가 가변이면 노드 간 높이 차이가 있을 때 경사로를 자동 생성하는가?

  - 모든 벽 높이 고정 상수
  - 노드별 높이 설정 가능, 인접 노드와 높이 차이는 급경사
  - 노드별 높이 설정, 자동 경사로 생성
  - 높이 외에도 상단/하단 Y값을 따로 제어 (바닥-천장 범위)

이유: 높이가 가변이면 데이터에 높이 필드가 필요하고, 경사로 처리 방식이 메시 생성 로직을 크게 복잡하게 만든다.

답: 질문의 표현이 헷갈림, y 좌표를 뜻하는거? 아님,기둥의 높이(길이)를 말하는거?

Q328. 바닥과 천장 자동 생성

※ 1단계 답변 반영: 참고: 벽은 정수 그리드의 노드를 직선으로 이어 만들고(대각선 가능), 프리팹으로 배치합니다(3단계 Q320, Q322, Q323). 대각선 벽이 있으면 벽으로 둘러싸인 영역이 격자 칸과 맞지 않으므로, 첫 번째 선택지의 '속한 셀'은 벽으로 둘러싸인 영역을 뜻하게 됩니다. 레이저 벽의 발사 장치는 천장에 붙이기로 해서(그림 확인 채팅, 그림 1) 레이저 벽이 있는 곳에는 천장이 있어야 합니다. 맵 전체에 천장을 둘지도 함께 정해 주세요. 천장을 두면 맵을 둘러싼 벽의 '높이 제한 없이'(4단계 Q195)는 천장으로 해결됩니다.

벽 노드로 벽을 만들 때 바닥(floor)과 천장(ceiling)도 자동으로 생기는가? 아니면 별도 노드/기물로 지정해야 하는가?

  - 벽을 만들 때 자동으로 속한 셀의 바닥/천장도 생성
  - 바닥과 천장을 별도 노드 타입으로 명시적 지정
  - 바닥/천장은 기본 제공하지 않고 프리팹으로 별도 배치

    해소: 그림 확인 채팅(그림 1)에서 레이저는 위로 올라가며 천장의 발사 장치 쪽으로 사라지게 했고, 다시 켜질 때는 반대로 내려오는 것으로 이해했습니다. 두 번째 선택지(상단부터 순차)에 가깝고, 프리팹 하나를 늘리는 방식(4단계 Q465)이라 레이저 면을 위로 줄이거나 셰이더로 표현합니다.
  - Q397. 레이저 벽 시각 표현
    질문: 레이저 벽(여러 칸을 차지하는 통행 방해 기물)을 무채색 월드에서 어떻게 시각화할 것인가? 그리드 라인, 에너지 장벽, 입자 라인, 반투명 볼륨 등?
    해소: 그림 확인 채팅(그림 1)에서 반투명한 면(두 번째 선택지 '반투명 빛나는 장벽 메시'에 가까움)과 천장에 붙은 발사 장치로 정했습니다. 색은 미정이고(그림의 빨간색은 구분용), 레이저 벽마다 색을 다르게 할 수 있다고 가정하고 설계합니다.
  - Q403. 오브 라벨 형식(3D 모델 기반)
    질문: v1은 그리드 셀 위에 '02 01 00' 같은 공백 구분 라벨을 붙였는데, v2는 3D 오브 모델 위에 어떤 형식의 라벨을 표시할 것인가? (같은 텍스트, 아이콘, 컬러칩 등)
