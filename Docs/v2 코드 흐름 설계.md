## 0. 이 문서에 대해

- **범위**: 코어 루프(결정 로그 9절, 3차 Q490)를 자세히 쓴다. 체크포인트·저장·이어하기·'처음부터'·메뉴 흐름은 코어 루프 뒤에 만들지만, 그때 코어 루프 코드를 고치지 않도록 **들어갈 자리**만 정한다.
- **수준**: 무엇이 무엇을 맡는지, 누가 누구를 부르는지, 어떤 데이터와 이벤트가 오가는지까지 쓴다. 함수는 대표적인 것만 적는다.
- **이름**: 새로 만드는 것은 역할을 나타내는 한글 이름(예: 맵 매니저, 지금 색, 레이저 벽)으로 쓴다. 이미 정한 코드 이름(`ColorValue`, `RequiredColorBase`)과 지금 있는 클래스 이름(`GameManager`, `InputManager` 등)은 그대로 쓴다. 코드 이름은 처음 나오는 곳(절 제목, 표)에 한글 이름 옆에 적는다(예: 맵 매니저(`MapManager`), 코드 이름 Q515). 이름 규칙은 결정 로그 10절에 있다.
- **[제안]**: 여러 방법 중 하나를 고른 곳이다. 고른 방법과 다른 방법을 함께 적고, 15절에 번호(Q493~)를 붙여 모았다. 결정 로그에는 '(코드 흐름 Q###)'로 인용한다. 2026-10-28에 모두 제안대로 정해졌다.

## 1. 설계 기준

세 목표를 코드 규칙으로 옮겼다.

- **확장성**: 새 기물·팝업·노드 종류를 더할 때 **기반 클래스를 상속하거나 인터페이스를 구현하고 프리팹을 만드는 것**으로 끝나게 한다. 맵 매니저, 조준, 저장, UI는 기물의 종류를 몰라도 동작한다.
- **유지보수**: **규칙**(무엇이 맞는가), **겉모습**(어떻게 보이는가), **연결**(누가 누구에게 알리는가)을 나눈다. 하나의 결정은 한 곳에서만 바뀐다(판정은 코어 규칙, 수치는 설정 애셋, 소리는 소리 연결).
- **개발 편의**: 규칙은 Play 없이 EditMode 테스트로 확인한다. 맵 씬은 Play 한 번으로 바로 시험한다. 맵 실수는 에디터 검사가 먼저 잡는다. 수치는 인스펙터에서 바꾼다.

규칙

1. **의존은 한 방향이다.** 월드(기물·플레이어·맵)와 UI는 코어 규칙에 기대고, 코어 규칙은 아무것도 모른다. 월드는 UI 클래스를 모르고, 둘은 이벤트와 인터페이스로만 만난다.
2. **규칙은 순수 C#이다.** MonoBehaviour가 아니고 씬 없이 만들 수 있어 테스트할 수 있다.
3. **기물 컴포넌트는 세 가지만 한다.** 입력을 받아 규칙을 부르고, 상태를 바꾸고, 이벤트를 보내거나 겉모습에 알린다.
4. **겉모습은 따로 둔다.** 문짝 움직임, 레이저 흐려짐, 강조, 흔들림, 색 표시는 별도 컴포넌트다. 로직은 상태만 알리므로 아트를 바꿔도 로직은 그대로다.
5. **같은 씬 안의 연결은 인스펙터 참조**, 씬을 넘는 연결(맵 씬 ↔ UIScene)은 EventBus나 등록식 접근점으로 한다.
6. **전역 싱글톤은 늘리지 않는다.** 지금 있는 전역 서비스만 쓰고, 맵 범위의 것은 맵 씬마다 있는 맵 매니저를 거친다.
7. **수치는 설정 애셋 한 곳**에 둔다.
8. **맵 설계 규칙 중 기계로 확인할 수 있는 것은 에디터 검사**가 잡는다.

## 2. 큰 그림

```
  ┌ UI (UIScene, additive) ──────────────────────────────────────┐
  │ 조준 값 표시 · 지금 색 표시 · 일시정지 · 클리어 화면 · 팝업 호스트 │
  └──────────────┬────────────────────────▲──────────────────────┘
                 │ 팝업 등록                │ EventBus 이벤트
  ┌ 월드 (맵 씬) ─▼────────────────────────┴──────────────────────┐
  │ 맵 매니저 · 플레이어(이동·조준·지금 색·뷰모델) · 기물 · 노드 시스템 │
  └──────────────┬────────────────────────────────────────────────┘
                 │ 호출
  ┌ 코어 규칙 (asmdef, 순수 C#) ▼─────────────────────────────────┐
  │ ColorValue · 색 규칙 · 지금 색                                  │
  │ 팝업 호스트 인터페이스 · 스냅샷 데이터 · 노드 데이터              │
  └───────────────────────────────────────────────────────────────┘
  전역 서비스 (씬이 바뀌어도 남음, 지금 있는 것):
  GameManager · InputManager · GameAudio · SaveManager · SceneLoader · UIManager
```

- **어셈블리**: 코어 규칙만 asmdef 하나로 묶고(테스트용 asmdef 하나 더), 월드와 UI는 기본 어셈블리(Assembly-CSharp)에 둔다. asmdef로 묶은 코드는 기본 어셈블리를 참조할 수 없으므로, 월드·UI까지 묶으면 `GameManager`, `InputManager` 같은 지금 코드를 쓸 수 없다. 반대로 기본 어셈블리는 asmdef를 자동으로 참조하므로 월드·UI에서 코어 규칙을 바로 쓴다. 이 구조 덕분에 규칙 1(코어 규칙은 아무것도 모름)은 컴파일러가 지켜 준다.
- 코어 규칙은 UnityEngine의 값 타입(`Color`, `Vector3`)은 써도 되지만 MonoBehaviour와 씬 오브젝트는 쓰지 않는다.
- 새 코드는 모두 `ColorMaze` 네임스페이스 하나에 둔다(3차 Q489, 코드 이름 Q507). 어셈블리 이름은 코어 규칙 `ColorMaze.Assembly`, 테스트 `ColorMaze.Assembly.Tests`다. v1 코드는 v2 코드를 쓰기 전에 지우므로(14절 0단계) v1 이름과 겹칠 일이 없다.

## 3. 씬과 수명

### 3.1 씬 구성

- **부팅 씬**(`Boot`, 새로 만듦)에서 `Bootstrap`이 전역 서비스를 깨우고 다음 씬을 불러온다(코어 루프 동안은 시험 씬, 메뉴 흐름을 만들 때 메인 메뉴로 바꿈). 맵 씬은 `SceneLoader`로 불러오며, UIScene은 `UIManager`가 늘 additive로 얹는다(2차 Q288).
- **맵 씬**에는 맵 매니저(`MapManager`) 1개, 플레이어(`Player` 프리팹) 1개, 시작 지점(`StartPoint`) 1개, 노드 그래프(`NodeGraph`) 1개(벽·문·레이저 벽), 설치형 기물이 있다.
- **맵 씬 기본 프리팹**(`MapRoot`): 맵 매니저 + 플레이어 + 노드 그래프 루트를 하나로 묶어, 새 맵은 이 프리팹을 끌어다 놓고 시작한다(설정 애셋 연결도 프리팹에 들어 있음).

### 3.3 맵 매니저의 수명

- 맵 씬마다 하나 있고 씬과 함께 생기고 사라진다(DontDestroyOnLoad가 아님). v1 `LevelManager`처럼 씬이 바뀔 때마다 목록을 다시 모으는 일이 없다.
- '지금 맵'을 정적 접근점 하나로 내놓는다(Awake에서 설정, OnDestroy에서 해제). 맵 범위의 것을 찾는 길은 이것 하나다.
- 기물보다 먼저 깨어나도록 실행 순서를 앞에 둔다. 기물은 OnEnable에서 등록하고 OnDisable에서 해제한다.
- 시작할 때: 상태가 Playing이 아니면 Playing으로 맞추고(열린 맵에서 바로 시작한 경우), 플레이어를 시작 지점으로 옮기고, 클리어 시간을 0으로 두고, '맵 시작' 이벤트를 보낸다. 2단계에서는 앞의 둘만 만들었다. 클리어 시간은 7단계에서 더했고(맵 씬과 함께 새로 생기므로 0부터, 10.1), '맵 시작' 이벤트는 받는 곳이 생길 때 더한다(2차 Q267).

### 3.4 열린 맵에서 바로 시작 (`DirectPlayLoader`) [제안 Q495]

- v1의 에디터 스크립트 `PlayFromMainMenu`는 Play를 누르면 늘 MainMenu부터 시작했다. v2에서는 Play를 늘 부팅 씬(`Boot`)부터 시작하고, 3차 Q490의 '시험 씬을 에디터에서 바로 열어 확인'을 위해 예외를 둔다.
- **제안**: 에디터 메뉴에 켜고 끄는 항목 'Play: 열린 맵에서 바로 시작'을 둔다(켜짐 여부는 EditorPrefs에 기억). 켜져 있고 열린 씬이 부팅 씬이 아니면, Play를 눌렀을 때 부팅 씬에서 평소처럼 부팅한 뒤 **열려 있던 씬을 바로 불러온다**(에디터 전용 코드). 부팅 순서를 그대로 쓰므로 부팅 씬에만 있는 설정(`GameAudio`의 클립 연결 등)이 빠지지 않는다. Build Settings에 없는 씬도 에디터에서는 경로로 불러온다.
- 다른 방법: 부팅 오브젝트를 프리팹으로 묶어 맵 씬에서도 부팅한다. 부팅 경로가 둘이 되어 고칠 곳이 늘어난다.
- 바로 시작은 디스크의 씬을 불러오므로, 켜져 있을 때 Play를 누르면 고친 씬을 먼저 저장할지 묻는다(취소하면 Play도 취소, 2단계 구현).

## 4. 코어 규칙 (순수 C#)

### 4.1 ColorValue

- `ColorValue { int r, g, b }` 구조체(2차 Q101). 덧셈·뺄셈, `==`/`!=`, 가장 큰 채널, 'R G B' 문자열(예: `2 0 0`). 지금 색, 색 원천의 값, 요구 색이 모두 이 타입이다. 색 시스템 개편에서 `OrbValue`의 이름을 바꾸고 뺄셈(레이저 벽)을 더했다.
- 인스펙터에 보이도록 직렬화 필드를 두지만 코드에서는 값으로만 다룬다(바꿀 때는 새 값을 만듦).
- 채널 한도도 채널마다 따로인 세 정수라 이 타입으로 나타낸다(1단계 구현).

### 4.2 색 규칙 (`ColorRules`)

채널 한도는 **채널마다 따로인 값**(기본 (5,5,5), 모든 맵 같음, 결정 로그 '색 시스템 개편')으로 인자로 받는다. 그래서 테스트에서는 아무 값이나 넣을 수 있다. 색 시스템 개편에서 `OrbRules`의 이름을 바꿨다.

- **한도 안인가**: 모든 채널이 0~그 채널의 한도.
- **자르기**: 채널마다 0~그 채널의 한도로 자른다(음수는 0, 넘치면 한도). 흡수한 지금 색이 거친다(넘친 값은 사라짐, v1처럼 0부터 다시 세는 순환은 쓰지 않음).
- **이상인가**(`IsAtLeast`): 모든 채널이 빼는 색의 그 채널 이상인가(레이저 벽을 지날 수 있는가).
- **요구 색으로 쓸 수 있는가**(`IsValidRequired`): 모든 채널 1 이상, 세 채널이 모두 같지 않음(2차 Q373, Q455), 한도 안(넘으면 지금 색이 닿을 수 없음). 에디터 검사가 끼운 문·목적지에 쓴다.
- **색 원천 값으로 쓸 수 있는가**: (0,0,0)과 세 채널이 같은 값이 아님(2차 Q455). 에디터 검사가 레이저 벽의 빼는 색에도 쓴다(12절).
- **색**: 가장 큰 채널로 나눈 정규화 RGB(늘 최대 밝기, 2차 Q262). **발광 세기**는 가장 큰 채널에 비례(계수는 설정 애셋, 2차 Q412). **흑백 변환**은 채도만 0(밝기 계산 방식은 구현 때, 2차 Q170). (0,0,0)의 색은 검정으로 둔다(1단계 구현). 흑백 밝기는 **세 채널의 평균**이다(순수 빨강·초록·파랑이 같은 회색, 4단계, 4단계 구상 채팅).

### 4.3 지금 색 (`CurrentColor`)

- 플레이어가 든 색 하나다(결정 로그 '색 시스템 개편'). (0,0,0)에서 시작하고 채널 한도는 만들 때 받는다.
- **흡수**(`Absorb`): 더하고 자른다(넘친 값은 사라짐).
- **쓰기**(`TrySpend`): 요구 색과 **정확히 같으면** (0,0,0)으로 비우고 성공한다(끼운 문, 목적지). 다르면 그대로 두고 실패한다.
- **지날 수 있는가**(`CanPass`)와 **지나기**(`Pass`): 모든 채널이 빼는 색 이상이면 지날 수 있고, 지나면 뺀다. 모자라면 지날 수 없으므로 음수가 생기지 않지만, 혹시 모를 경우를 위해 0에서 멈추게 자른다.
- 값이 바뀔 때만 C# 이벤트 하나로 알린다(지금 색 컴포넌트가 '지금 색 바뀜'으로 보냄, 5.1).
- 되돌리기는 없다(재시작·체크포인트로만).

### 4.4 합성 세션 (없앰)

- 색 시스템 개편에서 소지 오브(`OrbInventory`, 항목 `HeldOrb`), 흡수 세션 자리(`AbsorbSession`)와 함께 없앴다. 오브·합성·제출의 코드 흐름은 태그 `0.0.1-alpha`의 이 문서에 남아 있다.

### 4.5 제출 세션 (없앰)

- 제출 세션(`SubmitSession`, `SubmitKind`, `SubmitOutcome`, `SubmitRejectReason`)을 없앴다. 끼운 문·목적지는 팝업 없이 조준 + 클릭으로 지금 색을 쓴다(7.4).

### 4.6 작동기 상태 (없앰)

- 작동기 상태(`ActuatorState`)를 작동기 계열과 함께 없앴다.

### 4.7 스냅샷 데이터 (`MapSnapshot`, 자리만, 체크포인트 단계에서 채움)

- 맵 스냅샷: 맵 id·맵 버전, 플레이어(위치·시선), 지금 색(색 시스템 개편 ← 소지 오브 값 목록·채널 한도), 기물 상태 목록(`FixtureStateEntry`: 맵 안 id + 상태), 맵 플레이 시간, 활성화된 체크포인트 id 목록(결정 로그 3절, 2차 Q450, 3차 Q488).
- **[제안 Q499]** 기물 상태는 **기물마다 자기 상태를 JSON 문자열로** 내보내고 스냅샷은 'id + 문자열' 목록으로 든다. 기물 종류가 늘어도 스냅샷 형식은 그대로다(JsonUtility는 여러 타입이 섞인 목록을 못 담음).
  - 다른 방법: 종류별 필드를 모은 큰 상태 클래스. 기물 종류가 늘 때마다 형식을 고쳐야 한다.

### 4.10 진행 저장 데이터 (`ProgressSave`, `MapRecord`, 진행 시스템 2단계)

- 저장 파일 `colormaze_save.json`의 내용(결정 로그 3절): 형식 버전(시맨틱 버전 2.0.0), 저장 시각(UTC), 맵 기록(맵 id, 클리어, 최고 시간), 체크포인트가 있는지 + 스냅샷 하나(4.7, 맵 id·맵 버전을 든다). JsonUtility는 null 객체를 쓰지 못해 '있는지'를 따로 든다.
- 규칙: 클리어 기록(최고 시간은 더 짧을 때만), 체크포인트 저장(덮어씀, 2차 Q449), 그 맵의 체크포인트 지우기(다른 맵 것은 그대로), 그 맵의 체크포인트 꺼내기(맵 버전이 다르면 버림, 3차 Q488).
- 파일 읽고 쓰기는 월드 쪽의 진행 저장소(`ProgressStore`, `Core/`, 설정과 같은 정적 저장소)가 SaveManager 범용 JSON API로 한다. 처음 읽을 때 v2 저장 파일이 없으면 v1 `save.json`·`stage_attempts.json`을 지운다(2차 Q452). 체크포인트 기록은 '처음부터'(`SceneRestarter`)와 클리어 때 지운다.
- 맵 목록(`MapList`, `Map/`, 애셋 `Assets/Data/MapList.asset`): 항목은 맵 id·씬 이름·표시 이름·썸네일·맵 버전(3차 Q487). 맵 기본 프리팹(`MapRoot`)의 맵 매니저가 든다.

### 4.8 노드 데이터 (`NodeGraphData`, `NodeData`, `WallData`, `DoorData`, `WallKind`, 계산은 `NodeGraphRules`)

- 노드·벽·끼운 문 항목 클래스(11.1). 유니티 에디터 맵의 노드 그래프와 UGC의 `CustomStageData`가 **같은 클래스**를 쓴다(2차 Q321).
- id는 노드·벽·끼운 문이 노드 그래프의 다음 id 하나를 함께 쓴다. 끼운 문의 위치는 구간의 첫 벽 모듈부터 센 모듈 수(문의 시작 쪽 가장자리)이고, 문 설정은 6단계에서 더한다. 문 폭은 임시값이라 계산 함수가 인자로 받는다(1단계 구현).
- 순수 계산: id 발급(맵 안에서 1부터 늘어나는 정수, 지운 번호는 다시 쓰지 않음, 2차 Q340), 같은 자리 노드 합치기(2차 Q352), 구간 길이로 모듈 수와 남는 길이 계산(2차 Q459), 문을 끼울 수 있는지(양옆에 문 폭 절반만큼 벽, 그림 0).
- 3단계에서 더한 계산: 편집(노드 더하기 — 같은 자리면 그 노드, 노드 지우기 — 붙은 벽도, 벽 잇기 — 같은 노드·이미 이어진 두 노드는 거부(높이가 다른 노드 거부는 층간 이동을 없애며 뺌), 벽 지우기), 모양(첫 모듈 위치 — 남는 길이를 양 끝에 반씩, 콜라이더 구간, 문을 끼울 수 있는 위치의 범위, 바닥·천장 판). 합치기는 같은 두 노드를 잇게 된 벽을 하나만 남긴다.

## 5. 플레이어

### 5.1 플레이어 프리팹 (`Player`)

v1 `Player` 프리팹은 0단계에서 지우고(14절) 같은 이름으로 새로 만든다(코드 이름 Q510). 이동 컴포넌트도 v1을 참고해 새로 쓴다.

| 부분 | 맡는 것 |
|---|---|
| 이동 (`FirstPersonController`) | v1 `FirstPersonController`를 참고해 새로 쓴다. 게임플레이 입력이 잠겨 있으면 이동·회전하지 않는다. 수치는 v1 값에서 시작해 조정(2차 Q211, Q212). 피벗은 발밑(CharacterController 중심 높이 0.8)이라 시작 지점 위치로 바로 옮기고, 카메라 눈높이는 1.3이다(2단계 구현). |
| 조준 컨트롤러 (`InteractionController`, 새로) | 매 프레임 상호작용 거리만큼 화면 중앙으로 레이캐스트해 조준 대상을 고른다. 보일 값이 바뀌면 '조준 대상 바뀜'을 보낸다. 좌클릭이면 대상과 상호작용한다. 입력이 잠겨 있거나 일시정지 중이면 아무것도 안 한다. |
| 지금 색 컴포넌트 (`PlayerColor`) | 코어 규칙의 지금 색(4.3)을 들고(채널 한도는 설정 애셋), 바뀌면 '지금 색 바뀜'을 보낸다. 시작할 때도 한 번 보낸다(처음부터 다시 해도 UIScene은 남아 있으므로 지금 색 표시를 맞춤). |
| 뷰모델 (`ColorViewmodel`) | '지금 색 바뀜'을 받아 오른손 위의 구 하나를 칠한다(색은 정규화 RGB, 발광은 가장 큰 채널에 비례, (0,0,0)이면 숨김). '색 흡수'를 받아 손을 뻗는 연출을 한다(손은 임시 모양). |

- 4단계 구현
  - 조준 컨트롤러는 맞은 콜라이더의 부모에서 기물 기반을 찾고, 상호작용할 수 있으면 좌클릭으로 상호작용한다. '조준 대상 바뀜'은 받는 곳(조준 값 표시)을 만드는 8단계에서 더한다. 뷰모델에는 콜라이더가 없어 레이캐스트에 걸리지 않는다.
- 8단계 구현
  - 조준 컨트롤러는 상호작용할 수 없는 대상도 값 제공으로 값을 읽고, (보일 값이 있는가, 값)이 바뀔 때만 '조준 대상 바뀜'을 보낸다(값을 보이는 쪽만 받으므로 같은 값의 다른 대상으로 옮겨도 보내지 않음). 입력이 잠기거나 일시정지면 대상이 비므로 팝업·일시정지·클리어 화면에서 값 표시가 숨는다.
  - (색 시스템 개편에서 없앰) 소지 오브 컴포넌트의 Tab 인벤토리 창.
  - 플레이어 문맥은 조준 컨트롤러가 깨어날 때 만들어 든다.
  - 뷰모델(임시 모양)은 **뷰모델 레이어(`ViewModel`)만 그리는 오버레이 카메라**를 메인 카메라의 스택에 두어 벽에 붙어도 손이 벽에 묻히지 않는다(메인 카메라는 이 레이어를 그리지 않음).
- 색 시스템 개편 구현 (2026-11-01)
  - 지금 색 컴포넌트(`PlayerInventory`에서 이름을 바꿈)는 깨어날 때 맵 매니저의 게임 규칙에서 채널 한도를 읽는다(맵 매니저가 먼저 깨어남).
  - 플레이어 문맥은 지금 색 컴포넌트를 들고 지금 색(`Color`)은 쓸 때 읽는다(같은 오브젝트의 컴포넌트끼리는 Awake 순서가 정해져 있지 않음).
  - 뷰모델(`OrbViewmodel`에서 이름을 바꿈): 회색 상자 손 위 `SphereAnchor` 아래에 구 하나(`ViewmodelSphere` 프리팹 인스턴스)가 떠 있다. '색 흡수'를 받으면 손을 뻗었다 돌아오고 구가 색 원천 쪽에서 날아와 자리에 든다(0.6초). '색 거부'를 받으면 손과 구가 짧게 흔들린다(임시).
- v1 `InteractionController`는 v1 필터(`FilterBlockBase`)에 기대므로 재사용하지 않는다. 0단계에서 v1과 함께 지우고, 같은 이름으로 새로 쓴다(코드 이름 Q510).

### 5.2 기물이 플레이어를 찾는 방법 [제안 Q500]

- **제안**: 기물은 전역 플레이어 Instance를 찾지 않는다. 조준 컨트롤러가 상호작용할 때 **플레이어 문맥**(`PlayerContext`: 지금 색, 플레이어 위치, 이동 컴포넌트)을 넘긴다. 맵 매니저도 플레이어를 들고 있다(시작 지점으로 옮기기, 스냅샷).
- 다른 방법: v1처럼 플레이어 정적 Instance. 어디서나 플레이어에 손댈 수 있어 의존이 보이지 않게 된다.

### 5.3 입력 (`InputManager`, v1 참고해 새로 씀)

- (색 시스템 개편에서 없앰) **Tab**: 인벤토리 창이 없어져 읽지 않는다.
- **게임플레이 입력 잠금**: '잠근 쪽' 목록을 들고 하나라도 있으면 잠김이다. 팝업이 잠그고, 나중에 확인 창 등도 같은 방법으로 잠근다. 이동과 조준 컨트롤러가 이 잠금을 본다. 일시정지는 지금처럼 `Time.timeScale = 0`으로 멈춘다.
- **ESC**는 뒤로 가기 스택이 받는다(7.8).

## 6. 기물

### 6.1 공통 기반 (`FixtureBase`)과 인터페이스

```
FixtureBase (v2 기물 기반: 맵 안 id, 맵 매니저 등록, 강조, 상태 저장 기본 구현)
 ├ RequiredColorBase (요구 색 기반: 요구 색, 요구 색 칠하기, 값 제공)
 │   ├ GateBase (문 계열 기반: 막는 콜라이더)
 │   │   ├ Door (끼운 문)
 │   │   └ LaserWall (레이저 벽)
 │   └ Goal (목적지, 작동기 계열. 기반 ActivatorBase는 둘째 종류가 생길 때)
 ├ ColorSource (색 원천, 사물마다 프리팹)
 └ SpawnPointBase (출발점 기반: 위치·시선)
     ├ StartPoint (시작 지점)
     └ Checkpoint (체크포인트, 코어 루프 뒤)
```

- 계열과 종류는 `Docs/v2 기물 분류.md`가 단일 출처다(코드 이름도 그 문서의 표). 색 시스템 개편으로 작동기 계열과 오브 편집기 계열을 없앴고, 개편 뒤 사용자가 기물 분류 편집기로 계열을 다시 정했다(2026-11-01): 목적지는 작동기 계열(`Fixtures/Activators/`)이고, 성질(색상 제출 등)은 지금은 문서에만 둔다. 계단 계열은 층간 이동을 없애며 지웠다. 요구 색 기반은 요구 색을 가진 기물(끼운 문, 레이저 벽, 목적지)이 같이 쓰는 부분이다. 끼운 문과 레이저 벽의 **모양**은 노드 시스템 쪽 컴포넌트(`DoorPiece`, `LaserSegment`, 11.4)가 맡는다.

| 인터페이스 | 뜻 | 구현하는 것 |
|---|---|---|
| 상호작용 (`IInteractable`) | 지금 상호작용할 수 있는가, 상호작용(플레이어 문맥) | 색 원천, 끼운 문, 목적지 |
| 값 제공 (`IValueProvider`) | 보일 값이 있는가, 그 값(`TryGetDisplayValue`, 8단계) | 색 원천(흡수 전), 요구 색 기반(끼운 문은 닫혀 있을 때만, 레이저 벽, 목적지) |
| 상태 저장 (`ISnapshotable`) | 상태 내보내기(JSON 문자열, 없으면 null)·불러오기(연출 없이 바로) | 끼운 문, 색 원천, 레이저 벽(상태 없음, 복원 때 지나감 추적만 비움). 기반의 기본 구현은 두지 않고 상태가 있는 기물만 붙인다(진행 시스템 1단계) |

- **상호작용과 값 제공을 나눈 이유**: 레이저 벽은 상호작용하지 않지만 빼는 색을 보인다. 흡수한 색 원천과 열린 문은 둘 다 안 된다(색 시스템 개편 전에는 다 쓴 일회용 작동기가 이유였다, 3차 Q478). 작동 대상(`IActuatorTarget`)은 작동기와 함께 없앴다.
- **상호작용 강조**: 상호작용할 수 있는 동안 늘 약하게 강조한다(2차 Q193). 기반이 '상호작용할 수 있는가'가 바뀔 때 강조 겉모습 컴포넌트(`InteractHighlightView`)를 켜고 끈다. 강조 방법과 색은 미정이라 겉모습 컴포넌트 하나만 바꾸면 된다.
  - 4단계 임시 효과: 자체 발광을 숨 쉬듯 약하게 올렸다 내린다(흰색, 재질에 발광이 켜져 있어야 함). v1의 조준 아웃라인(`Outline.mat`, `InteractionHighlightOutline` 셰이더)은 쓰지 않아 '!!!!'를 붙였다(4단계 구상 채팅).
  - 발광 재질은 GI 플래그(Global Illumination)를 `RealtimeEmissive`로 둔다. URP는 이 플래그에 발광이 없으면 재질을 다시 불러올 때 `_EMISSION`을 지워 발광이 꺼진다(4단계 재질에서 생긴 문제를 5단계에서 고침).
- **맵 안 id**(`FixtureId`): 맵 안에서 1부터 늘어나는 정수(3차 Q487). 에디터가 발급하고(`FixtureIdAssigner`) 검사한다(12절).

### 6.2 색 원천 (`ColorSource`)

- 컴포넌트 하나를 사물마다 다른 프리팹(이름은 사물 이름, 예: 소화기)에 붙인다(코드 이름 Q508, 결정 로그 10절). 색 시스템 개편 뒤에는 '추출 오브젝트' 대신 '색 원천'이라 부른다(코드 이름은 그대로).
- 인스펙터: 값(`ColorValue`), 색을 칠할 렌더러 목록, 오브젝트 밝기(아트용, 값과 무관, 2차 Q454).
- 상호작용: 지금 색에 더한다(4.3, 늘 성공). 흡수됨으로 바꾸고, 흑백으로 칠하고, 강조를 끄고, '색 흡수'(위치·값)를 보낸다. 한 번만 흡수할 수 있다.
- 값 제공: 흡수 전만. 상태 저장: 흡수됨 여부(복원하면 칠하기와 강조를 다시 맞춤).
- 4단계 구현: 값의 색은 `MaterialPropertyBlock`으로 칠해 에디터에서도 보인다. 이벤트의 위치는 칠하는 첫 렌더러의 가운데다. 임시 프리팹은 회색 원기둥 `FireExtinguisher`(소화기)다. 색 시스템 개편 전의 '추출 불가'(소지 오브가 가득 참)는 없다.

### 6.3 합성기 (없앰)

- 합성기(`ColorMixer`)와 오브 편집기 계열(필터·복제기·증폭기는 계획만 있었음)을 색 시스템 개편에서 없앴다.

### 6.4 목적지 (`Goal`)

- 색 시스템 개편에서 작동기 계열(`SubmittableObjectBase`, `ActuatorBase`, 일회용·반복 작동기)과 제출 팝업을 없애고, 목적지는 요구 색 기반을 상속한다.
- 끼운 문과 같은 방식이다: 조준 + 좌클릭 → 지금 색이 요구 색과 정확히 같으면 지금 색을 쓰고((0,0,0)으로 비움) 맵 매니저에 클리어를 요청한다(7.6). 다르면 흔들림(`ShakeView`)과 '색 거부'. 클리어한 뒤에는 상호작용하지 않는다(강조 끔). 맵당 1개(에디터 검사).
- 임시 프리팹은 넓고 낮은 원판이고 위쪽 띠가 요구 색이다(든 오브 구는 없앰). 흔들림은 루트를 오른쪽 방향으로 흔든다.

### 6.5 문 계열 (`GateBase`)

- **요구 색 기반**(`RequiredColorBase`): 요구 색(`RequiredColor`, 읽기 전용으로 내놓아 맵 검사와 정답 검증 도구가 읽음, 2차 Q263), 요구 색 렌더러를 요구 색으로 칠함(에디터에서도 보임), 값 제공. 끼운 문·목적지는 정확히 같아야 하고 레이저 벽은 빼는 색으로 쓴다.
- **문 계열 기반**: 막는 콜라이더(상자) 목록과 막음 상태. 막음을 바꾸는 함수 하나가 콜라이더만 켜고 끈다(2차 Q277, 루트와 스크립트는 늘 켜 둠). 언제 막는지와 겉모습은 종류마다 다르다. 연결된 작동기 목록, AND 계산, 연결색, '플레이어 위로 닫히지 않게'(회수 거부)는 작동기와 함께 없앴다.
- **종류**
  - 끼운 문(`Door`, 모양은 `DoorPiece`): 노드 시스템이 일반 벽 구간에 끼워 만든다(2차 Q464). 조준 + 좌클릭 → 지금 색이 요구 색과 정확히 같으면 지금 색을 (0,0,0)으로 비우고 연다: 막음 끔, 겉모습(`DoorView`, 가운데서 갈라지는 양쪽 미닫이, 그림 0), 강조 끔, '문 열림'. 한 번 열리면 계속 열려 있어 닫힐 때의 처리가 없다. 다르면 흔들림과 '색 거부'(지금 색은 그대로). 값 제공은 닫혀 있을 때만.
  - 레이저 벽(`LaserWall`, 모양은 `LaserSegment`): 노드 사이 구간 하나(2차 Q460). 상호작용은 없다. '지금 색 바뀜'을 받아 지금 색의 모든 채널이 빼는 색 이상이면 막지 않는다(겉모습 `LaserWallView`: 반투명 레이저 면이 흐려짐, 임시). 플레이어가 레이저를 다 지나 반대쪽으로 나가면 지금 색에서 빼고 '레이저 통과'를 보낸다(양쪽 방향 모두, 들어갔다 되돌아오면 빼지 않음).
    - 지나감 판정: 깨어날 때 막는 콜라이더(레이저 면)와 같은 자리·크기의 트리거 상자를 루트에 더한다. 플레이어가 들어올 때 루트 앞 방향과의 내적 부호로 들어온 쪽을 기억하고, 나갈 때 쪽이 다르면 지나간 것이다. CharacterController는 움직이지 않는 트리거와도 트리거 알림을 받는다.
    - 플레이어 위로 켜지지 않게: 플레이어가 트리거 안에 있는 동안은 막지 않던 레이저를 켜지 않고, 나갈 때 다시 본다.
- **상태 저장**: 끼운 문은 열림 여부(복원은 미닫이 없이 바로 `DoorView.SetOpenImmediate`), 레이저 벽은 상태가 없다(지금 색에서 다시 계산). 레이저 벽은 복원 때 '안에 있음'을 비운다: 순간이동은 트리거 나감을 보내지 않아, 레이저 안에서 돌아가면 레이저가 다시 켜지지 않기 때문이다.
- 색 시스템 개편 구현 (2026-11-01): 임시 겉모습은 문 위 띠(`RequiredColor`, 재질 `Temp_RequiredColor`)와 레이저 발사 장치가 요구 색이다. 문짝 강조를 위해 `Temp_Door`에 발광을 켰다. 흔들림(`ShakeView`, 끼운 문·목적지가 같이 씀)은 루트를 오른쪽 방향으로 0.3초 흔든다. 레이저 면은 지날 수 있으면 0.4초 동안 불투명도 0.45 → 0.12로 흐려진다(재질 `Temp_Laser`는 투명). 문짝 미닫이는 6단계 그대로(0.5초).

### 6.6 출발점 계열 (`SpawnPointBase`)

- 출발점 기반: 위치와 시선 방향.
- 시작 지점(`StartPoint`): 맵당 1개(에디터 검사). 맵 매니저가 시작할 때 플레이어를 여기로 옮긴다.
- 체크포인트(`Checkpoint`): 같은 기반을 상속한다. 같은 오브젝트의 트리거(1 × 2 × 1)로 닿음을 재고, 처음 닿을 때만 맵 매니저에 스냅샷을 요청한다. 활성화 여부는 기물 상태가 아니라 스냅샷의 활성화된 체크포인트 목록에 든다. 임시 겉모습은 바닥의 얇은 원판(콜라이더 없음, 재질 `Temp_Checkpoint`)이고 활성화되면 색이 바뀐다(진행 시스템 1단계).

### 6.7 계단 계열 (없앰)

- 층간 이동을 없애(2026-11-01, 결정 로그 '층간 이동 없앰') 맵은 한 층이다. 계단 계열(`FloorMoveBase`, 계단·점프패드·낙하구간)은 만들지 않는다.

### 6.8 새 기물을 더하는 방법

| 더할 것 | 하는 일 | 고치지 않아도 되는 것 |
|---|---|---|
| 요구 색을 쓰는 새 기물 | 요구 색 기반 상속(쓰는 방식), 프리팹 | 요구 색 칠하기, 조준 값 표시, 맵 검사(요구 색 규칙) |
| 새 문 계열 종류 | 문 계열 기반 상속(언제 막는지), 겉모습 컴포넌트, 노드 시스템 종류 | 조준, 맵 매니저 |
| 새 설치형 기믹 | `FixtureBase` + 필요한 인터페이스(상호작용·값 제공·상태 저장) | 조준, 맵 매니저, 스냅샷 |
| 새 팝업 | 세션(코어 규칙) + 팝업 화면, 팝업 호스트에 화면 등록 | 입력 잠금, ESC, 커서 |
| 새 소리 | 소리 연결에 '이벤트 → 소리' 한 줄 | 소리를 내는 기물 |

## 7. 흐름

### 7.1 조준과 값 표시

1. 조준 컨트롤러가 화면 중앙으로 상호작용 거리만큼 레이캐스트한다. 가장 가까운 것 하나만 맞으므로 벽 너머는 안 된다. 큰 기물은 콜라이더 전체가 대상이라 표면 어디를 조준해도 된다(2차 Q214).
2. 맞은 콜라이더의 부모에서 v2 기물 기반을 찾는다.
3. (보일 값이 있는가, 값)이 바뀌었을 때만 '조준 대상 바뀜'을 보낸다. 흡수 직후처럼 같은 대상의 값이 없어져도 여기서 잡힌다(8단계에서 대상은 비교에서 뺌, 5.1).
4. UI의 조준 값 표시가 조준점 오른쪽 위에 'R G B' 상자를 보이거나 숨긴다(2차 Q461).

### 7.2 흡수

1. 좌클릭 → 조준 대상이 상호작용할 수 있으면 상호작용(플레이어 문맥).
2. 색 원천이 지금 색에 더한다(채널마다 자름, 넘친 값은 사라짐).
3. 흡수됨, 흑백, 강조 끔. 지금 색이 바뀌었으면 '지금 색 바뀜' → 뷰모델의 구 색, 지금 색 표시, 레이저 벽(막을지 다시 봄). 이어서 '색 흡수' → 소리, 뷰모델의 손 뻗기와 구가 날아옴(0.6초, 보이기만, 2차 Q232).
4. 다음 프레임에 조준 컨트롤러가 값이 없어진 것을 보고 값 표시를 숨긴다.

### 7.3 합성 (없앰)

- 색 시스템 개편에서 합성기와 함께 없앴다.

### 7.4 끼운 문·목적지에 색 쓰기

1. 끼운 문·목적지를 조준하고 좌클릭 → 상호작용(닫힌 문, 클리어 전 목적지만).
2. 지금 색이 요구 색과 **정확히 같으면** 지금 색을 (0,0,0)으로 비운다 → '지금 색 바뀜'.
   - 끼운 문: 열림(계속 열려 있음), 막음 끔, 문짝 미닫이, 강조 끔, '문 열림'(소리).
   - 목적지: 맵 매니저의 클리어(7.6).
3. 다르면 그 기물이 흔들리고 '색 거부' → 소리, 뷰모델의 손 흔들림. 지금 색은 그대로다(글 알림 없음).
- 팝업이 없으므로 입력 잠금·뒤로 가기 스택을 거치지 않는다. 그래서 목적지가 바로 `GameManager.ClearMap()`을 불러도 상태가 Playing이다.

### 7.5 레이저 벽 지나기

1. '지금 색 바뀜'(플레이어가 시작할 때 한 번 포함) → 레이저 벽마다 지금 색의 모든 채널이 빼는 색 이상인지 다시 본다.
2. 지날 수 있으면 막음을 끄고 레이저 면이 흐려진다. 모자라면 막는다(플레이어가 레이저 자리에 있으면 나갈 때까지 기다림).
3. 플레이어가 레이저를 다 지나 반대쪽으로 나가면 지금 색에서 빼고 '레이저 통과'(소리) → '지금 색 바뀜' → 남은 색으로 다시 1.
4. 들어갔다 같은 쪽으로 나오면 빼지 않는다.

### 7.6 클리어

1. 목적지에 맞는 색을 씀(7.4) → 맵 매니저의 클리어.
2. 맵 매니저: 클리어 시간을 멈추고, '맵 클리어'(맵 id, 클리어 시간)를 보내고, `GameManager.ClearMap()`(상태 Cleared).
3. 임시 클리어 화면: '맵 클리어'를 받아 시간을 보이고, 시간을 멈추고 커서를 보인다(v1과 같은 방식). 버튼은 다시 하기(임시로 `SceneRestarter`)와 종료(`GameManager.QuitGame`). 메인 메뉴가 아직 없어 메인 메뉴 버튼은 메뉴 흐름을 만들 때 더하고(7단계 구상 채팅), '다음 맵'은 맵 목록 애셋을 만든 뒤 더한다.
4. 맵별 최고 기록 저장은 코어 루프 뒤: 전역 진행 쪽이 '맵 클리어'를 받아 저장한다(2차 Q468).
- 7단계 구현: 클리어 시간은 상태가 Playing인 동안만 흐르므로, Cleared가 되면 따로 멈추지 않아도 멈춘다. 클리어 화면(`MapClearScreen`)은 UIScene에 두고 일시정지 메뉴와 같은 모양(어두운 배경과 상자)이며, 시간은 '클리어 시간 mm:ss.ss'로 보인다. `timeScale`이 0이라 조준·이동·상호작용이 멈추고, 상태가 Cleared라 ESC로 일시정지가 열리지 않는다. 시험 씬의 목적지는 요구 값 (1,3,1)로 레이저 20 너머에 두었다(7단계 구상 채팅). 색 시스템 개편 뒤의 시험 맵은 14절.

### 7.7 인벤토리 창 (없앰)

- 색 시스템 개편에서 없앴다(소지 오브와 늘어나는 한도가 없어지고 지금 색은 HUD에 늘 보임, 8.4). Tab도 읽지 않는다.

### 7.8 ESC와 일시정지 — 뒤로 가기 스택 [제안 Q494]

- **제안**: 닫을 수 있는 화면(팝업, 나중에 확인 창·설정 패널)은 열 때 뒤로 가기 스택에 '닫기'를 넣고 닫을 때 뺀다. ESC는 스택 맨 위의 닫기를 부르고, **스택이 비어 있을 때만** 일시정지를 열고 닫는다(설계 문서 7.1, 2차 Q194). 일시정지 메뉴(`PauseMenu`, v1 `PauseMenuController`를 참고해 새로 씀)는 스택이 비었을 때만 ESC로 열고 닫는다. 코어 루프 동안은 '계속·처음부터·종료'만 두고, 설정 등은 메뉴 흐름에서 더한다(작업 순서 채팅).
- 다른 방법: 일시정지 메뉴가 '팝업이 열려 있는가'를 직접 확인한다. 닫을 화면이 늘 때마다 조건을 더해야 한다.
- 팝업은 상태(`GameState`)가 아니다. 팝업 중에도 클리어 시간은 흐르고(설계 문서 8.3), 일시정지는 팝업이 없을 때만 열린다.
- 5단계 구현: ESC는 일시정지 메뉴가 읽는다(`InputManager.ReadCancel`). 일시정지는 상태를 Paused로 바꾸고 `Time.timeScale = 0`으로 멈추고, 커서를 보이고, 스택에 '계속'을 넣는다. '처음부터'(`SceneRestarter`)는 시간을 되돌리고 지금 맵 씬을 이름으로 다시 불러온다(Build Settings에 있어야 함). '처음부터'·'종료'의 확인 창(2차 Q453)은 메뉴 흐름 때 더한다(5단계 구상 채팅). 에디터의 게임 뷰는 ESC를 누르면 스크립트와 상관없이 커서 잠금을 풀므로, 에디터에서 ESC로 닫으면 게임 뷰를 한 번 클릭해야 다시 잠긴다. 빌드에서는 생기지 않아 그대로 둔다(5단계 확인 채팅).

## 8. UI

### 8.1 팝업 호스트 (`PopupHost`, 인터페이스 `IPopupHost`, 접근점 `Popups`) [제안 Q493]

- **제안**: UIScene의 팝업 호스트가 켜질 때 **정적 접근점에 자기를 등록**한다. 인터페이스는 코어 규칙 쪽에 둔다(세션만 주고받으므로 순수 C#). 기물은 '팝업 열기(세션, 닫힐 때 할 일)'만 부르고 UI 클래스를 모른다. 등록된 호스트가 없으면 오류 로그로 바로 드러난다.
- 다른 방법: EventBus로 '팝업 열기 요청'을 보낸다. 닫힐 때 결과를 돌려받으려면 요청에 콜백을 실어야 하고, 받을 UI가 없으면 요청이 조용히 사라진다.
- 맡는 것: 한 번에 팝업 하나(열려 있으면 다른 열기는 무시), 세션 종류에 맞는 화면 고르기, 게임플레이 입력 잠금, 커서, 뒤로 가기 스택, 닫기 버튼, '팝업 열림·닫힘' 이벤트.
- 팝업 화면은 세션 종류마다 하나이고 호스트에 등록한다(6.8 '새 팝업').
- 5단계 구현: 팝업 화면의 기반은 `PopupView`(이 세션을 그리는가, 그리기, 숨기기)이고 호스트의 화면 목록에 넣는다. 열면 커서를 풀고 닫으면 다시 잠근다. 열린 채로 맵 씬을 다시 불러오면 스택과 잠금만 치운다. '팝업 열림·닫힘' 이벤트는 만들지 않았다: 팝업이 열리면 입력이 잠겨 조준 대상이 비므로 조준 값 표시가 저절로 숨는다(8단계 구상 채팅). 8단계에서 인벤토리 창을 Tab으로 닫으려고 `Popups.Close`를 더했다. 색 시스템 개편에서 쓰는 곳이 없어진 `Popups.Close`를 빼고 합성·제출 화면과 인벤토리 창을 없애, 지금은 등록된 팝업 화면이 없다. 팝업 기반(호스트, 뒤로 가기 스택, 입력 잠금, 커서)은 다음 팝업(확인 창 등)을 위해 남긴다.

### 8.2 값 상자 (`ColorValueLabel`, 공통 UI 부품)

- 'R G B' 값 상자는 부품 하나다(그림 2·3·5). 채널 글자 3개라 프리팹 배치만 달리해 같이 쓴다. 조준 값 표시와 지금 색 표시가 쓴다. 색 시스템 개편에서 `OrbValueLabel`의 이름을 바꿨다.
- 오브 칸(`OrbCellView`, 프리팹 `Prefabs/UI/OrbCell`·`EmptyOrbSlot`·`PopupSymbol`)은 합성·제출 화면, 인벤토리 창과 함께 없앴다.

### 8.3 합성 화면과 제출 화면 (없앰)

- 색 시스템 개편에서 합성 화면(`MixPopup`), 제출 화면(`SubmitPopup`), 인벤토리 창(`InventoryPopup`)을 없앴다.

### 8.4 HUD

- 조준점: 흰색 '+', 색이 바뀌지 않는다(2차 Q193). v1 `CrosshairController`의 색 바꾸기는 v2에서 쓰지 않는다.
- 조준 값 표시(`AimValueLabel`): '조준 대상 바뀜'을 받는다. 팝업이 열리면 숨긴다(입력이 잠겨 조준 대상이 비므로 따로 듣지 않음, 8단계). 8단계 구현: 값 상자(8.2)는 조준점에서 오른쪽 위로 24픽셀 떨어져 있다.
- 지금 색 표시(`CurrentColorHud`, 색 시스템 개편): '지금 색 바뀜'을 받아 왼쪽 아래(가장자리에서 24픽셀)에 색 견본(40 × 40, 정규화 RGB, (0,0,0)은 검정)과 'R G B' 값 상자를 늘 보인다. 자리와 모양은 임시다(결정 로그 '색 시스템 개편'의 [미정]).
- 임시 클리어 화면(`MapClearScreen`): 7.6.

### 8.5 v1 UI

- v1 UI는 UIScene과 함께 모두 14절 0단계에서 지우고, UIScene은 v2 UI만으로 새로 만든다(작업 순서 채팅). 그래서 v1과 같이 있는 동안의 처리([제안 Q498]: 같은 UIScene의 v2 UI 루트, v1 전용 UI 숨김)는 필요 없어졌다(코드 이름 Q505).

- 색 시스템 개편에서 없앤 이벤트: 소지 오브 바뀜(`InventoryChanged`), 추출함(`OrbExtracted` → 색 흡수), 추출 불가(`ExtractRejected`), 합성함(`OrbsMixed`), 제출 결과(`SubmitAttempted`), 작동기 바뀜(`ActuatorStateChanged`), 문 계열 바뀜(`GateStateChanged` → 문 열림), 자리만 있던 오브 흡수함·채널 한도 바뀜.

- 이벤트는 `Scripts/Events/`에 이벤트마다 파일 하나로 둔다(readonly struct, 4단계).
- **소리 연결**(`SoundEventPlayer`, 애셋 `SoundEventConfig`) [제안 Q502]: 이벤트를 받아 소리를 내는 컴포넌트 하나에 '이벤트 → 소리'를 모은다. 기물은 `GameAudio`를 직접 부르지 않는다. 소리를 바꾸거나 더할 때 이곳만 고치고, 소리 5종(2차 Q400)의 믹서 그룹 나누기도 여기서 한다.
  - 다른 방법: 기물이 `GameAudio`의 함수를 직접 부른다(v1 방식). 소리가 기물 코드 곳곳에 흩어진다.
- 8단계 구현: 이벤트에는 받는 곳(소리)에 필요한 것만 담았다(기물·위치는 받는 곳이 생기면 더함). 소리 연결은 맵 기본 프리팹(`MapRoot`)에 두고 `AudioManager.PlaySFX`로 낸다(위치 없는 2D 소리). 효과음은 모두 SFX 믹서 그룹으로 나가고, 5종 그룹 나누기는 소리마다 음량을 정하는 설정 화면을 설계할 때 한다(8단계 구상 채팅).

## 10. 맵 매니저와 설정

### 10.1 맵 매니저 (`MapManager`)

코어 루프에서 맡는 것

- 지금 맵 정보: 맵 목록(`MapList`)에서 자기 씬 이름으로 찾은 항목(맵 id, 맵 버전, 3차 Q487). 없으면 오류 로그(맵 검사도 알림).
- 저장(진행 시스템 2단계): 체크포인트에 처음 닿으면 스냅샷을, 클리어하면 클리어·최고 시간을 진행 저장소에 넣고 바로 파일에 쓴다(클리어는 그 맵의 체크포인트도 지움). 시작할 때 그 맵의 체크포인트 기록이 있고 맵 버전이 같으면 시작 지점 대신 그 스냅샷으로 시작한다(메인 메뉴 전까지의 임시 자동 이어하기, 플레이 시간도 이어짐).
- 기물 등록부: 맵 안 id → 기물. id가 겹치면 오류 로그.
- 플레이어 참조, 시작 처리(3.3).
- 클리어 시간: `Time.deltaTime`을 더한다. 일시정지(`timeScale` 0)에는 멈추고 팝업 중에는 흐른다(2차 Q468). 7단계에서 상태가 Playing일 때만 더하게 만들었다(팝업은 상태가 아니므로 흐르고, 일시정지·클리어 뒤에는 멈춤).
- 클리어(7.6).
- 설정 애셋을 들고 플레이어와 기물에 나눠 준다(10.2).

뒤에 들어올 자리(코어 루프 코드를 고치지 않고 더함)

- 스냅샷 만들기: 등록부의 상태 저장을 모은다 + 플레이어(체크포인트의 자리와 방향, 2차 Q450) + 지금 색 + 시간 + 활성화된 체크포인트.
- 스냅샷 복원('체크포인트로', 검은 화면 사이): 기물 상태 불러오기(열린 문, 흡수한 색 원천, 오브젝트별 복원, 2차 Q307)와 체크포인트 활성화 → 플레이어 위치 → 지금 색(`CurrentColor.Restore`) → '지금 색 바뀜'(레이저 벽이 막을지 다시 봄). 플레이 시간은 되돌리지 않는다. 체크포인트 전이면 '처음부터'.
- '처음부터'는 씬 재로드(`SceneRestarter`, 진행 시스템 구상 채팅). 이어하기는 저장 단계.
- 낙사 안전망(2차 Q139): 게임 중 플레이어가 월드 높이 −낙사 깊이(게임 규칙 `fallDepth`, 기본 10) 아래면 마지막 체크포인트 자리(없으면 시작 지점)로 옮기기만 한다.

### 10.2 설정 애셋 [제안 Q501]

| 설정 애셋 | 담는 것 |
|---|---|
| 게임 규칙 (`GameRulesConfig`) | 채널 한도 (5,5,5)(색 시스템 개편에서 기본 채널 한도를 `channelLimit`으로 바꾸고 슬롯 수를 뺌), 상호작용 거리(3, 9단계에서 걸어 보며 정함), 발광 세기 계수(지금 색 구, 임시 0.2: 블룸이 꺼져 있어 1을 넘는 발광은 더 밝아 보이지 않으므로 값 1~5가 0.2~1이 되게 함, 4단계) |
| 기준 치수 (`NodeBuildConfig`) | 벽 두께 0.2, 기둥 0.3 × 0.3, 벽의 키 3(정수), 문 폭 1·높이 2.0, 판 두께 0.1, 노드 시스템이 쓰는 프리팹(벽 모듈, 기둥, 문, 레이저, 바닥·천장 타일) (3차 Q484, 9단계에서 걸어 보며 확정: 문 높이만 2.2 → 2.0). 모듈 길이 0.25는 끼운 문의 위치 단위라 코어 규칙의 상수로 둔다(3단계). |
| 연결색 목록 (`LinkColorConfig`) | (색 시스템 개편에서 없앰) |
| 소리 연결 (`SoundEventConfig`) | 이벤트 → 소리 클립. 지금은 있는 소리로 임시 연결(8단계 구상 채팅, 색 시스템 개편에서 다시 이음): 색 흡수 `brush`, 색 거부 `Nope`, 문 열림 `switch-a`, 레이저 통과 `tap-a`, 체크포인트 도달 `switch-b`, 맵 클리어 `Clear` |

- 맵 씬 기본 프리팹(`MapRoot`)의 맵 매니저가 이 애셋들을 참조한다. 에디터 도구는 애셋을 직접 찾는다. 애셋 파일은 `Assets/Data`에 둔다(코드 이름 Q514).
- 다른 방법: 각 컴포넌트 인스펙터에 수치를 흩어 둔다. 같은 값을 여러 프리팹에서 고쳐야 한다.

## 11. 벽 노드 시스템

### 11.1 데이터

- **노드 그래프** 컴포넌트(`NodeGraph`, 맵마다 1개)가 노드 목록, 벽 목록, 다음 id를 든다. 항목 클래스는 코어 규칙의 노드 데이터(4.8)다.
- 노드: id, 정수 좌표 (x, y, z). y는 늘 0이다(맵은 한 층, 층간 이동 없앰).
- 벽: id, 양 끝 노드 id, 종류(일반 벽 / 레이저 벽), 재질 번호(2차 Q354), 끼운 문(id, 위치 0.25 단위, 설정).
- 끼운 문에도 id가 있다. UGC 맵에서 작동기 연결을 id로 담기 때문이다(3차 Q487, 작동기는 색 시스템 개편에서 없앰).
- 노드 그래프는 맵 씬에 **따로 둔 루트 오브젝트**다. 맵 기본 프리팹(`MapRoot`) 안에 두면 만든 벽이 전부 프리팹 오버라이드가 되기 때문이다. 노드 좌표는 노드 그래프 기준이다(3단계).

### 11.2 만들기 (벽 빌더 `NodeGraphBuilder`)

- **같은 빌더**를 에디터(유니티 에디터 맵, Undo 기록)와 런타임(UGC 맵)에서 쓴다(2차 Q458).
- 일반 벽 구간: 루트 오브젝트(데이터 id를 기억) 아래에 0.25 모듈 반복, 콜라이더 상자 하나(2차 Q330). 노드마다 기둥을 두고 남는 길이는 기둥이 가린다(2차 Q459).
- 끼운 문: 구간 안에서 문 자리만 모듈을 비우고 문 프리팹(문 계열)과 문 위 벽을 놓는다.
- 레이저 벽: 레이저 프리팹 하나를 구간 길이에 맞게 늘리고(2차 Q465), 천장 장치를 붙인다.
- 바닥·천장: 모든 노드를 감싸는 사각형 안에 1×1 타일을 바닥(높이 0)과 천장(벽의 키 높이)에 깐다(2차 Q473). 층간 이동 칸을 빼는 일은 층간 이동을 없애며 지웠다(6.7).
- 에디터 맵에서 만든 오브젝트는 static으로 표시한다(정적 배칭·라이트맵).
- 3단계 구현
  - 임시 회색 프리팹은 1×1×1 상자이고 빌더가 기준 치수로 늘린다. 9단계에서 숫자만 바꿔 걸어 볼 수 있다. 진짜 모양이 오면(월드/아트) 프리팹이 치수를 갖게 바꾼다.
  - 구간 끝에 남는 길이는 양 끝에 반씩 나눈다(한쪽 0.125 미만, 기둥 0.3이 가림).
  - 콜라이더: 문이 없는 구간은 노드에서 노드까지 상자 하나, 문이 있는 구간은 문 양옆 둘과 문 위 벽 하나. 기둥에도 콜라이더를 둔다(기둥이 벽보다 굵어 모서리가 튀어나옴).
  - 끼운 문은 문 프리팹의 루트(`DoorPiece`)를 벽 구간 루트의 자식으로 둔다(문짝 반쪽 둘, 닫힌 채). 레이저 벽은 레이저 프리팹의 루트(`LaserSegment`)를 구간 가운데에 두고 레이저 면만 늘린다.
  - 바닥·천장 판은 (x, 판 높이, z) 칸 목록으로 계산한다(높이, z, x 순서). 층간 이동을 없앤 뒤로는 한 층만 계산한다.
  - static 표시는 프리팹에 해 둔다(문짝·레이저는 움직이므로 뺌). 에디터에서 만들고 고치고 지우는 것은 Undo에 기록한다(`NodeBuildOps`).

### 11.3 다시 만들기 [제안 Q496]

- **제안**: 다시 만들 때 **데이터 id로 지금 오브젝트와 비교**한다.
  - 남은 id: 오브젝트를 지우지 않고 위치·길이와 안쪽 모듈만 다시 만든다.
  - 없어진 id: 지운다. 새 id: 만든다.
  - 그래서 끼운 문·레이저 벽의 인스펙터 값(요구 색, 색 시스템 개편 전에는 연결된 작동기 목록·연결색)과 다른 기물이 그 오브젝트를 가리키는 참조가 남는다. 미정 표의 '노드를 고쳐 다시 만들 때 인스펙터 값을 지키는 방법'(2차 Q458)을 이 방법으로 정한다.
  - 규칙: 손으로 넣는 값은 루트 오브젝트의 컴포넌트에 둔다. 루트 아래 '만든 부분'은 다시 만들 때 지워진다.
- 벽 종류가 바뀌면(일반 벽 ↔ 레이저 벽) 루트를 새로 만든다. 기둥·바닥·천장은 손으로 넣는 값이 없어 통째로 다시 만든다(3단계).
- 다른 방법: 에디터 맵도 UGC처럼 연결을 id로 들고 다시 만든 뒤 다시 잇는다. 인스펙터 직접 참조(2차 Q266)와 어긋난다.

### 11.4 상속 구조

```
NodeObjectBase (노드 시스템 기물 기반: 데이터 id, 만들기·다시 만들기)
 ├ WallSegment (일반 벽 구간: 모듈, 기둥, 콜라이더, 끼운 문 자리)
 ├ DoorPiece (끼운 문의 모양: 일반 벽 구간이 만드는 자식)
 └ LaserSegment (레이저 벽 구간의 모양)
```

- 노드 시스템 기물 기반은 **모양**을 맡고(2차 Q357), 문 계열 기반(6.5)은 **동작**을 맡는다. 끼운 문과 레이저 벽은 두 컴포넌트를 같은 오브젝트에 붙인다(`DoorPiece` + `Door`, `LaserSegment` + `LaserWall`). C#은 클래스 하나만 상속하므로 모양과 동작을 나눠야 둘 다 상속 구조를 쓸 수 있다.
- 이동 발판 같은 새 종류는 노드 쪽을 상속하고 필요한 동작 컴포넌트를 붙인다.

### 11.5 노드 편집 도구 (`NodeGraphWindow` + `NodeGraphSceneTool`, 첫 범위)

- 전용 에디터 창 + 씬 뷰 조작(2차 Q331, Q343).
- 첫 범위(시험 맵을 만들 만큼, 3차 Q490): 노드 찍기(정수 스냅)·고르기·끌어 옮기기·지우기, 두 노드 잇기·벽 지우기, 벽 종류 바꾸기, 문 끼우기(위치), 다시 만들기, Undo/Redo(2차 Q351), 같은 자리 노드 자동 합치기(2차 Q352).
- 나중: 재질 고르기 화면, 여러 개 고르기, 각도 스냅(필요하면, 2차 Q345).
- 3단계 구현
  - 편집 동작은 `NodeGraphEditing`이 창과 씬 뷰 도구에 함께 준다. 편집마다 데이터 변경 → 같은 자리 노드 합치기 → 다시 만들기를 Undo 하나로 묶는다.
  - 씬 뷰 도구(노드 그래프를 고르면 툴바에 나타남): 빈 곳 클릭은 노드 찍기(높이 0), 노드·벽 클릭은 고르기, **Shift+클릭은 고른 노드에서 벽 잇기**(빈 곳이면 노드를 찍고 이어 연달아 그림, 3단계 구상 채팅), 끌기는 노드 옮기기(놓을 때 다시 만듦), Delete는 고른 노드(붙은 벽 포함)나 벽 지우기.
  - 창(메뉴 `ColorMaze/노드 편집`): 노드·벽 목록, 고른 노드의 위치(x·z), 고른 벽의 종류와 문 끼우기·위치(끼울 수 있는 범위만), 다시 만들기 버튼. 노드 그래프가 없으면 만들기 버튼을 보인다.

## 12. 에디터 검사 (`MapValidator`)

- 메뉴는 `ColorMaze/` 아래에 둔다(예: ColorMaze/맵 검사, ColorMaze/Play: 열린 맵에서 바로 시작, 코드 이름 Q511).
- 메뉴 하나로 지금 맵을 검사하고, 가벼운 검사는 씬을 저장할 때 자동으로 한다.
- 검사하는 것
  - 맵 안 id: 겹침, 빈 id(고침 버튼으로 다시 발급)
  - 시작 지점 1개, 목적지 1개
  - 색 원천의 값이 규칙에 맞는가(4.2)
  - 요구 색(색 시스템 개편): 끼운 문·목적지는 요구 색 규칙(한도 안 포함), 레이저 벽의 빼는 색은 색 원천 값 규칙 + 한도 안. 한도는 맵 매니저의 게임 규칙에서 읽고, 없으면 경고만 하고 이 검사를 건너뛴다. 빼는 색에 0인 채널을 허용할지는 [미정]이라 지금은 허용한다.
  - 노드: 노드 그래프 1개, 같은 자리 노드, 없는 노드를 가리키는 벽, 문을 끼울 수 없는 위치(3단계에서 만듦), 높이(y)가 0이 아닌 노드(층간 이동을 없애며 '높이가 다른 노드를 잇는 벽' 검사를 바꿈)
- 맵 안 id 발급: 기물을 놓거나 복제하면 에디터가 다음 번호를 준다. 첫 버전은 '검사 + 고침 버튼'으로 시작해도 된다. 2단계에서 메뉴 `ColorMaze/맵 검사`(맵 매니저 1개, 맵 안 id, 시작 지점 1개)와 `ColorMaze/맵 안 id 고치기`로 만들었고, 맵 씬을 저장할 때 맵 안 id를 자동으로 검사한다.
- 6단계에서 요구 값과 작동기 연결 검사를 더했다. 경고(어느 목록에도 없는 작동기, 빈 목록)도 문제 수에 센다. 색 시스템 개편에서 작동기 연결 검사를 빼고 요구 값 검사를 요구 색 검사로 바꿨다.
- 7단계에서 목적지 1개 검사를 더했다. 맵 안 id 고치기는 고친 뒤 Undo 기록을 바로 마무리하고 씬 변경 표시를 직접 한다. 프리팹 인스턴스의 Undo 기록은 프레임 끝에 처리되어, 고친 프레임에 저장하면 저장 뒤 씬이 다시 '바뀜'이 되고(이 때문에 테스트 실행이 '씬 저장' 창에 막힘), 인스턴스 값만 바뀌면 씬 변경 표시가 붙지 않았다.
- 검사하지 않는 것: '같은 연결색을 서로 보이는 곳에 두지 않음'은 기계로 정하기 어려워 맵 설계 규칙으로 사람이 지킨다(3차 Q492). 색 시스템 개편에서 연결색을 없애 해당이 없어졌다.
